<objective>
Rewrite all 22 tenant-scoped isolation policies to a single fail-closed, role-scoped predicate, and invert the pinned baseline test that currently documents the fail-open behaviour.

Purpose: SEC-03 and SEC-04. Today the same query silently returns zero rows or raises, depending only on a pooled connection's history — and application code routinely reads zero rows as "this record does not exist". Research verified against a live Postgres 17.10 that removing the null-tolerating guard is not sufficient: the second argument that makes the setting lookup itself tolerant must also go, or a genuinely untouched connection still returns zero rows instead of erroring.
Output: migration 0044 (22 policies, one predicate, explicit role scope), the sentinel treatment for the two pre-tenant lookup paths, and the inverted baseline assertions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code → RLS predicate | The predicate is the last line of defence; its failure mode determines whether a missing tenant context is caught or misread |
| pre-tenant lookup → tenant table | Two paths read a tenant table before any workspace is known; they must be grant-bearing, not predicate-bypassing |
