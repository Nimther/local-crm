<objective>
Close G-10-1: make `scripts/ensure-db-roles.mjs` load the external env file before it resolves its admin DSN, so the predev chain stops dying at step 2 on a machine whose Postgres has no `postgres` role.

Purpose: the script is the stale-volume bootstrap for the two roles this phase introduces — `mega_crm_scan` (D-01) and `mega_crm_auth` (D-04) — and it is wired ahead of migrations precisely because 0041/0042's GRANTs need those roles to exist. It resolves its DSN from bare `process.env` while every sibling DSN consumer first calls `process.loadEnvFile(resolveEnvPath())`, so `TEST_ADMIN_DATABASE_URL` from the external env file is invisible to it and it silently falls back to the compose-default constant. On a Homebrew Postgres that DSN has no such role, the script exits 1, and the `&&` chain aborts before `migrate-dev.mjs`. This is a documented recurrence of the 08-07 failure class (SPECIFICATION.md §3.1): the `TEST_ADMIN_DATABASE_URL`-override convention was copied from `provision-db.ts` without the env-loading half of the pattern — so the fix ships with a guard that makes the class non-recurring, not just this instance repaired.
Output: the one-line-class fix with an end-to-end subprocess proof, a predev-chain env-loading guard, and the spec/comment record of why the admin DSN vars are not in check-env.mjs's required list.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external env file -> predev script process | A DSN holding superuser credentials crosses here, from a file outside the repository working root resolved by `MEGA_CRM_ENV_FILE`/XDG precedence. |
| predev script process -> Postgres cluster | Role-creation DDL crosses here under a superuser connection — the highest-privilege connection any dev-time script in this repo opens. |
| test subprocess -> whatever DSN it inherits | The new tests spawn the real bootstrap CLI, so an inherited real DSN would put role-creation DDL on a live cluster during a test run. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-15-01 | Information disclosure | `scripts/ensure-db-roles.mjs` output path | medium | mitigate | The resolved DSN carries a superuser password; Task 1 forbids adding any log line that echoes it, leaving the existing per-role and failure lines as the whole output surface. Tests assert on the `host:port` substring node-postgres puts in its refusal message, never on a printed DSN. |
| T-10-15-02 | Tampering | test subprocess reaching a real cluster | medium | mitigate | Every sentinel DSN targets a loopback port with no listener, so the connection is refused before any `CREATE ROLE` statement executes; the child environment has both admin-DSN keys deleted, so it cannot inherit a real one from the developer's shell or the CI job. |
| T-10-15-03 | Information disclosure | temp env fixture in `scripts/__tests__/ensure-db-roles-env.test.mjs` | low | mitigate | Created with `mkdtempSync` under the OS temp directory, containing only obviously fake sentinel credentials, and removed in `afterAll`; no real DSN is ever written to it. |
| T-10-15-04 | Elevation of privilege | `MEGA_CRM_ENV_FILE` redirecting the superuser connection | low | accept | The variable is developer-controlled local configuration and already steers `DATABASE_URL` for the same chain via `check-env.mjs`/`migrate-dev.mjs` (08-15, QG-07). This plan adds no new surface — it brings the third chain member under the same, already-accepted model. |
| T-10-15-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing: no dependency is added to any `package.json`. `pg` and `vitest` are already root devDependencies. No package-legitimacy checkpoint is required because there is no install task to gate. |
</threat_model>
