<objective>
Prove cross-tenant denial by actively attempting it — through every API route module and every background-job family — rather than by asserting that the mechanisms which should prevent it are configured.

Purpose: SEC-16's first half, and SPEC R2's "no public-API code path can obtain cross-tenant read". Every prior plan in this phase asserted its own mechanism: a policy predicate, a role attribute, a grant, a response body. This plan asserts the outcome those mechanisms exist for, from the outside, which is the only assertion that survives a mechanism being refactored.
Output: two negative suites — one driving HTTP routes, one driving job handlers — each with a coverage assertion that fails when a module or job family is added without a case.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → every route module | The full attack surface a real tenant can reach; the only place denial can be proven end to end |
| hostile job payload → job handler | Background jobs take a workspace id as data; a crafted payload is the internal analogue of a crafted request |
| test suite → the phase's own claims | A suite that asserts mechanisms rather than outcomes passes while the outcome regresses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-14-01 | Information Disclosure | a route module bypassing the membership gate | high | mitigate | Every module has an attempted cross-tenant read whose denial is asserted from outside the handler |
| T-10-14-02 | Tampering | a cross-tenant write succeeding behind a 404 response | high | mitigate | Every denied write attempt re-reads the target workspace's row and asserts it unchanged |
| T-10-14-03 | Elevation of Privilege | a hostile job payload naming another workspace | high | mitigate | Per-family negative cases assert both workspaces' resulting state after a crafted payload |
| T-10-14-04 | Elevation of Privilege | the scan role reaching an ungranted table | high | mitigate | A runtime rejection test from the consumer side, complementing the earlier catalog assertions |
| T-10-14-05 | Repudiation | a new module or job family shipping without a negative case | high | mitigate | Both suites derive their expected set from the real registration lists, with explicit commented exclusion sets |
| T-10-14-06 | Tampering | a suite that passes vacuously | medium | mitigate | Every case attempts real access against seeded data in a second workspace; a fixture that failed to seed would fail its own positive control |
| T-10-14-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager installs in this plan (RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
