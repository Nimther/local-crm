<objective>
Create one shared redaction rule set, compiled two ways — into the structured logger's field configuration and into a recursive scrubbing function with no depth limit — and wire both the API and the worker to it.

Purpose: SEC-13. The API's logger already redacts four field names to a fixed nesting depth; the worker redacts nothing at all, and freeform event properties are exactly the shape a fixed-depth field list cannot cover. Phase 15's Sentry pre-send hook needs the same rules, and defining them twice is how they drift.
Output: a new `@mega-crm/redaction` workspace package, the API logger consuming its compiled field list, the worker's log surface consuming its scrubbing function, and a parity test guarding the two compiled forms against divergence.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application memory → log output | Decrypted provider keys, session tokens and contact PII pass through this boundary on every error path |
| freeform event properties → log output | Tenant-supplied JSON of unbounded shape and depth; a fixed field list cannot cover it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-13-01 | Information Disclosure | secrets in log output | high | mitigate | One rule table covering key names and value shapes, applied by both consumers; parity test asserts identical treatment of a representative payload |
| T-10-13-02 | Information Disclosure | PII nested deeper than the field list reaches | high | mitigate | Recursive scrubbing with no depth ceiling; the backstop probe asserts redaction at depth seven, which the path-list form cannot reach |
| T-10-13-03 | Information Disclosure | worker emitting unredacted output | high | mitigate | Every direct console call under the worker's source goes through the scrubbing wrapper, verified by grep |
| T-10-13-04 | Tampering | two rule lists drifting apart | medium | mitigate | Rules are declared in exactly one file; the parity test fails if the two compiled forms diverge |
| T-10-13-05 | Information Disclosure | narrowing coverage while centralizing | medium | mitigate | The previous path list is captured as a literal in the parity test and asserted still covered |
| T-10-13-06 | Denial of Service | recursion on a cyclic or very large object | medium | mitigate | Visited-object tracking terminates cycles; asserted by test |
| T-10-13-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager installs — the new package is workspace-internal source with no runtime dependencies (RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
