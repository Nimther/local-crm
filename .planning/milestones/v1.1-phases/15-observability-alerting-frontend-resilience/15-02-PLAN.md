<objective>
TRACER — one correlation identifier follows a single send end to end: HTTP request → BullMQ job → Postgres query, visible in structured logs on both sides.

Purpose: this is the phase's spine (D-07 / OPS-11 / OPS-12) and the thinnest slice that touches every layer the phase will later expand across. Proving it on one path first surfaces RESEARCH.md Pitfall 7 (nested `AsyncLocalStorage.run()` replaces rather than merges the store) before nineteen more workers and three Sentry SDKs are built on top of a context that silently drops its fields.
Output: a merge-safe correlation context in `packages/tenant-context`, a real Pino logger for `apps/worker`, `application_name` correlation in `withTenantTransaction`, and one wired path — `POST /api/campaigns/:id/test-send` → `email-broadcast` → `sends` write — carrying one id all the way through.

Scope discipline: exactly ONE call path is wired here. The other 19 worker factories and every other API route are expanded in plans 15-05 and beyond. This is a production-quality slice, not a prototype — nothing here is thrown away.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API | An inbound `x-request-id` header is attacker-controlled input that is echoed into logs and into a Postgres session parameter |
| API → queue → worker | Job payload crosses a process boundary and is deserialized by a possibly-older worker build |
| app → Postgres | `application_name` is written into a session parameter read by operators |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-04 | Tampering | `x-request-id` header echo in `genReqId` | medium | mitigate | Treat the header as an opaque correlation label only; never use it for authorization or dedup. Constrain accepted values to a bounded-length safe character set and fall back to `crypto.randomUUID()` otherwise, so a crafted header cannot inject separators into the composed `application_name` |
| T-15-05 | Information Disclosure | correlation fields stamped into every log line by `mixin()` | high | mitigate | The mixin returns only ids (`requestId`/`workspaceId`/`jobId`/`sendId`) — never contact data, never payloads. Pino redaction still applies to the rest of the line |
| T-15-06 | Denial of Service | `application_name` composed from unbounded inputs | medium | mitigate | Deterministic truncation to the versioned 63-byte budget before the `set_config` call, asserted by a test case |
| T-15-07 | Tampering | additive `requestId` on a job payload during rolling deploy | low | accept | Field is optional and ignored by an older worker build; no `schemaVersion` change, so the defer-unknown-version path is never triggered |
| T-15-SC | Tampering | npm/pip/cargo installs | high | mitigate | No installs in this plan — all dependency additions are gated by plan 15-01's blocking human legitimacy checkpoint |
</threat_model>
