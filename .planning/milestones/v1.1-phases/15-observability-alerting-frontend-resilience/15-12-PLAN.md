<objective>
The one schema change this phase needs: a keyed alert-dedup table for the four OPS-13 watchdogs, and a real rollup watermark for OPS-18.

Purpose: two later plans need database support that does not exist. The four new watchdogs need the atomic alert-claim primitive the existing watchdogs each got as their own singleton table — four more singleton tables would be four migrations, so this uses one keyed table instead, following `reputation_alert_state`'s keyed precedent. And D-12 assumes "the rollup watermark the API already knows" — it does not: `workspace_daily_rollup` has no update timestamp and there is no analytics-run health row, so the watermark has to be created before the frontend can render it honestly.
Output: migration 0064, the shared claim helper, watermark maintenance on both rollup write paths, and the analytics API exposing it.

Convention note: this repository allocates ONE migration slot per phase (see migration 0058's own header, which created a table for a later plan for exactly this reason). Plans 15-13 and 15-14 consume this migration; neither adds its own.
</objective>
