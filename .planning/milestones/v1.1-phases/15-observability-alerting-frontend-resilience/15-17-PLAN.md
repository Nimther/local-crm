<objective>
OPS-10: logs leave the host to a hosted provider — Grafana Cloud, per D-01 — with the backstop alerts an in-app watchdog structurally cannot provide.

Purpose: the four watchdogs from plans 15-13 and 15-14 run inside the API process — they cannot report that process, or the VPS, being dead. D-03's hybrid design gives that job to Grafana Cloud: a dead-man's-switch on "no logs received" plus an error-rate-spike rule. D-02 puts the shipping in a sidecar that tails Docker's own log capture, so delivery survives an application crash and also covers Postgres, Redis, Caddy and pgBackRest.
Output: an Alloy sidecar, bounded log rotation on every service, and the two backstop alert rules documented well enough to recreate.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VPS → Grafana Cloud | Container logs, including tenant-derived fields, leave the host to a third party over the network |
| Docker socket → Alloy container | Container-runtime discovery requires access to the host's Docker socket |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-59 | Elevation of Privilege | `/var/run/docker.sock` mounted into the Alloy sidecar | high | accept | Docker-socket access is effectively root-equivalent on the host, and Alloy's container discovery requires it. Mounted read-only, scoped to one pinned-tag first-party-vendor sidecar with no published port, and recorded here as an accepted risk of the chosen shipping mechanism (D-02) rather than mounted silently |
| T-15-60 | Information Disclosure | log lines containing tenant data leaving the host | high | mitigate | Redaction is applied at the source in both processes (plans 15-02/15-04/15-08); Alloy ships what the applications already redacted and adds no unredacted source |
| T-15-61 | Information Disclosure | Loki credentials in a committed file | high | mitigate | Configuration reads credentials from the environment; no value appears in `config.alloy` or `prod.env.example`, enforced by the names-only convention and asserted by the acceptance grep |
| T-15-62 | Denial of Service | unbounded json-file logs exhausting the VPS disk | high | mitigate | Bounded `logging:` blocks on every service, added in the same change that increases log volume |
| T-15-63 | Denial of Service | Loki index blow-up from high-cardinality labels | medium | mitigate | Correlation ids stay in the JSON body; labels limited to service, container and level, with the reasoning recorded in the config header |
| T-15-64 | Information Disclosure | plaintext log push | medium | mitigate | https push endpoint required, asserted in the environment example and the documentation |
| T-15-SC | Tampering | container image pull (`grafana/alloy`) | high | mitigate | Explicitly pinned immutable tag per this repo's GHCR convention; no mutable tag permitted by the prod-compose gate |
</threat_model>
