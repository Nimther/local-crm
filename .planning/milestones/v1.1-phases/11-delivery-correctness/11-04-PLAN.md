<objective>
Make `sends.id` a pure function of the send intent (UUIDv5, per D-09), closing the phantom-accepted-event correlation hole that `releaseDispatchClaim`'s `DELETE` plus `gen_random_uuid()` opens today.

Purpose: a 429/5xx release deletes the claim row. If SendGrid silently accepted the message anyway, the next retry gets a brand-new random id, the late webhook for the phantom message arrives with an id nothing recognizes, and the retry sends a genuine second email to the same contact. Deriving the id from the intent means the re-claim reproduces exactly the id SendGrid already holds.
Output: a `send-id.ts` primitive in `@mega-crm/delivery-core`, both claim gates and both exclusion writers using it, and a regression test that replays the release-then-re-claim cycle.
</objective>
