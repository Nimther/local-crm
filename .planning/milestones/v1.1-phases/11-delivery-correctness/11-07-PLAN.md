<objective>
Add SendGrid's `processed` event to the provisioned webhook subscription so the reconciler has direct, fast evidence that a message was accepted — and prove that ingesting it produces evidence and nothing else.

Purpose: the reconciler resolves from webhook evidence alone (D-05 — no provider API calls, the Email Activity API is a paid, rate-limited add-on the platform cannot assume under BYO keys). `delivered` can lag by minutes to hours; `processed` fires within seconds of acceptance and directly answers the only question `reconciling` asks. Without it, correct sends sit ambiguous far longer than they need to.
Output: `processed` in `EVENT_FLAGS`, tests pinning both the inclusion and the deliberate `deferred` exclusion, a regression test proving the new event type is inert beyond storage, and a runbook for bringing existing tenants forward.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| platform -> tenant's SendGrid account | Provisioning writes subscription configuration into a tenant's own account using their BYO key |
| SendGrid -> webhook ingestion | An untrusted external POST whose contents become the reconciler's only evidence |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-07-01 | Tampering | tenant webhook subscription | medium | mitigate | Only one additive flag changes; create and patch bodies are asserted identical so a reconnect cannot silently drop a previously-enabled event type; all eight pre-existing flags are asserted still true |
| T-11-07-02 | Denial of Service | `send_events` volume | medium | mitigate | `deferred` deliberately excluded (fires repeatedly per message); `processed` adds roughly one row per send into a monthly-partitioned table whose horizon is maintained by Phase 9's partition automation |
| T-11-07-03 | Spoofing | forged `processed` event as false acceptance evidence | high | mitigate | Unchanged and already closed upstream: the webhook route verifies the ECDSA signature against the raw body before parsing, and `send_id` correlation resolves only to rows inside the tenant's own workspace under RLS. This plan adds an event type to an already-authenticated channel, not a new channel |
| T-11-07-04 | Information Disclosure | provisioning error logs | medium | mitigate | Unchanged: `redactSecret`/`redactApiKey` already scrub the tenant key from every non-ok provisioning response log; this plan adds no new log site |
| T-11-07-05 | Repudiation | tenants not reprovisioned | low | accept | Accepted per D-06: existing tenants update through the recheck/reconnect path only. The reconciler accepts any correlated event as evidence, so the failure mode is slower resolution, not incorrect resolution. Documented in the new runbook and in SPECIFICATION.md rather than left implicit |
</threat_model>
