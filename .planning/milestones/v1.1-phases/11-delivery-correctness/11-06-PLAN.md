<objective>
Route every ambiguous provider outcome into `reconciling` on both send paths, and record how long the provider call took on every write.

Purpose: 11-03 proved the reconciler resolves rows that reach `reconciling` through the *interrupted-redelivery* door. This plan opens the other, far more common door — a call that timed out or was reset mid-flight — and closes the misclassification that started this phase: a request that may have been accepted is currently recorded as `failed`, telling an operator nothing was sent while a message sits in a recipient's inbox.
Output: a classified throw path around the provider call on both the campaign and the flow branch, the flow-side interrupted branch brought to parity with the campaign side, and duration columns populated on every write.
</objective>

## Trust Boundaries

| Boundary | Description |

| provider response/throw -> ledger status | The point where an external system's ambiguity becomes a durable claim about what happened to a recipient's mail |
| worker process -> campaign counters | Counter increments are irreversible and feed tenant-visible progress and completion |
