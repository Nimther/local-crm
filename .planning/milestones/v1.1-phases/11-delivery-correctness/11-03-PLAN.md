<objective>
Prove the whole delivery-correctness architecture end to end on one path: a campaign send interrupted after its claim was committed lands in `reconciling`, the new reconciler tick discovers it across workspaces, classifies it from webhook evidence alone, and resolves it to `sent` — with exclusive claiming on both sides of the race.

Purpose: this is the tracer. Every remaining plan expands outward from this slice (`unknown`, late-evidence re-scan, stale-`dispatching` sweep, timeout classification, deterministic ids, counter backfill, health alerting). Proving the wiring now — scan role, per-tenant claim, evidence correlation, sole-writer discipline, worker registration — means an architectural dead end costs one commit instead of eight.
Output: `send-reconciler.worker.ts` registered in the worker runtime, `resolveReconcilingSend` as the single audited exit from `reconciling`, the DLV-04 claim-gate refusal in both claim paths, and an end-to-end test that runs the whole path against live Postgres.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process -> cross-workspace scan role | The reconciler's discovery read crosses every tenant boundary at once, on `SCAN_DATABASE_URL` |
| reconciler <-> send worker | Two independent processes able to write the same ledger row |
| BullMQ payload -> worker | An at-least-once queue delivering a payload that may have been enqueued by an older or newer deploy |

FOR UPDATE SKIP LOCKED` inside `withTenantTransaction`, with the status re-verified inside the lock; `resolveReconcilingSend`'s own `WHERE status IN ('reconciling','unknown')` guard makes a lost race a no-op rather than a stomp |
