<objective>
Make the partition horizon maintain itself without anyone calling a function, and put the
dead hand in a different process from the hand it watches.

Purpose: plan 09-01 proved the detection-to-alert path but nothing runs it on a schedule
and nothing reads the operator's address. This plan adds the daily BullMQ tick with a
fixed-UTC-hour cron and a boot-time immediate run (D-07, D-13), registers it in the
worker composition root, introduces the operator-address configuration variable across
all three places this repository validates configuration, and starts the watchdog
interval inside the `apps/api` process — which is what makes it a genuine dead hand
rather than a self-report.

Output: `apps/worker/src/queues/partition-maintenance.worker.ts` registered in
`buildWorker()`, `OPERATOR_ALERT_EMAIL` enforced at API boot and at `predev`, and
`startPartitionWatchdog` running in `apps/api`'s `main()`.
</objective>

<flagged_assumptions>
**DB-02 (unclassified, unresolved)** — the spec-less edge probe produced no edge category
for "a missing partition raises an alert". Planner assumption: the edges that matter are
the four unhealthy conditions and the alert-cadence boundary, all of which are covered by
plan 09-01 task 2's test matrix, plus the "the job never ran at all" case, which is
covered here by the staleness threshold being evaluated against an absent row. If a
reviewer identifies a further DB-02 edge — for example an alert that fires while the
worker is mid-run and the row is momentarily stale by design — it is unplanned.

The watchdog's staleness threshold and the cron hour are related by arithmetic, not by a
shared constant: `STALE_THRESHOLD_HOURS = 26` is chosen for a once-daily `0 3 * * *`
schedule. Changing the cron to a different cadence without revisiting the threshold would
produce either a permanently-stale reading or a blind window. The two constants live in
different files by necessity (one is worker-side scheduling, one is API-side evaluation),
so this coupling is documented in both comments rather than enforced mechanically.
</flagged_assumptions>
