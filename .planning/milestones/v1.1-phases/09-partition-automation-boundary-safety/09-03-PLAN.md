<objective>
Give every ephemeral test database the same rolling partition horizon production has, and
put the month-boundary and calendar-precision behaviour under test.

Purpose: migrations create frozen partition months. A test database built from the
migration chain alone has partitions for a fixed window, so every insert in a test running
after that window silently lands in DEFAULT — which defeats any test that asserts
partition routing and hides the exact class of bug this phase exists to prevent. D-05
closes this by having the test fixture call the same `ensurePartitions` production calls.
This plan also delivers DB-04's boundary coverage for the automation path: month rollover
with an injected clock, idempotency, contiguity, and UTC bound alignment.

Output: the Drizzle schema declaration for the health table, `ensurePartitions` wired into
`packages/test-support`'s fixture, and two test suites — one asserting fixture parity, one
covering the boundary and precision behaviour.
</objective>
