<objective>
Build the spine this whole phase gates on: one programmatic migration runner that applies `packages/db/migrations` exactly once under a dedicated-connection advisory lock (D-12, DB-05), and `/healthz` + `/readyz` on the API where readiness independently verifies applied-vs-shipped migrations (D-13, OPS-04/OPS-05/DB-06). ROADMAP orders OPS-04/OPS-05 before OPS-02 precisely so deployment automation can gate on readiness instead of a timer — nothing else in this phase can be built correctly before this exists.

Purpose: every later plan in this phase (deploy script, compose healthchecks, worker health server, rollback rehearsal) consumes this contract. It is also where the phase's only MEDIUM-risk unknown lives — RESEARCH.md Open Question 1 / assumption A4: whether drizzle detects pending migrations by hash-set membership or by timestamp cutoff. Resolve that against the installed source and reuse the migrator's own answer.
Output: `packages/db/src/migration-journal.ts` (one definition of "applied"), `scripts/migrate-runner.mjs` (the one-shot migrate step), `apps/api/src/modules/ops/health.ts` (`/healthz`, `/readyz`), a fail-closed onRequest readiness guard, and tests that prove the 503→200 flip, exactly-once concurrency, and loud bounded failure.
</objective>
