## Planner decision to record: scheduled tick versus operator-only

CONTEXT.md and RESEARCH.md both leave this to the planner, noting Phase 9's D-08 precedent that destructive *row relocation out of the DEFAULT partition* was made operator-invoked only. This plan schedules the drop on the existing daily tick, behind a default-off enable flag, for three reasons that distinguish the two cases:

1. DB-11's wording is "retention данных определён и **применяется**" — an operator remembering to run a command monthly is not "applies".
2. Phase 9's operator-only rule governed an operation whose *target* depended on data inspection (which rows belong where). Retention's target is a pure function of the calendar and the catalog, with no judgement per invocation.
3. The judgement that does exist — is deleting data this old acceptable — is made once, when the flag is turned on, and that is a human gate placed after the restore drill.

The conservatism Phase 9 was protecting is preserved by construction instead: strictly-older-than eligibility, a catalog-driven walk, evidence tables excluded by an explicit list, no row-level DELETE anywhere, and every drop recorded. Record this decision and its reasoning in the SUMMARY, because it is a deliberate divergence from a prior phase's convention.
