<objective>
Close DB-12: add the constraints the database is actually missing, after proving both what is missing and that the existing data can carry them. RESEARCH.md's static schema read names `member(organizationId, userId)` as the one confirmed structural gap (Better Auth's own table — no application code declares it) and `invitation(organizationId, email)` as an unconfirmed secondary candidate; RESEARCH.md Open Question 2 explicitly asks for a live introspection pass rather than a repeat of that static read.

Purpose: an invite-accept race can plausibly have written two membership rows for the same person in the same organization, and every permission decision in the platform resolves through membership. The constraint is the fix; the pre-check is what stops the fix from being applied as an INVALID, silently non-enforcing index (Pitfall 17).
Output: a reusable live-introspection audit script, a read-only duplicate-count script, migration 0062 built on migration 0057's proven shape, and a test that proves both the refusal path and the enforcement.
</objective>

## Documented deviation from the ROADMAP's literal wording

The ROADMAP and CONTEXT.md say `CREATE UNIQUE INDEX CONCURRENTLY` + `ADD CONSTRAINT ... UNIQUE USING INDEX`. Migration 0057 — the precedent both documents tell this plan to cite rather than re-derive — establishes in its own header that `CONCURRENTLY` **is not expressible** inside drizzle's migration model, because each migration file runs as a single implicit transaction and `CREATE INDEX CONCURRENTLY` cannot run inside a transaction block. 0057 therefore used a blocking build plus the `indisvalid` assertion, and STATE.md records Pitfall 17 as closed by exactly that pattern. This plan follows 0057: blocking `CREATE UNIQUE INDEX`, then `ADD CONSTRAINT ... UNIQUE USING INDEX`, then the `indisvalid` assertion. `member` holds one row per user per organization — a blocking build is milliseconds, and the write-blocking window 0057 had to reason about at `send_events` scale does not exist here. The guarantee the ROADMAP asked for (no INVALID, non-enforcing index) is delivered in full; only the mechanism differs, for a reason the repository already documented. Record this in the SUMMARY.
