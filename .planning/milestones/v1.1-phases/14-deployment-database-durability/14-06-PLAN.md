## Facts established during planning (do not re-derive)

- `API_PORT` defaults to **4000** (`apps/api/src/env.ts`). Caddy proxies to `api:4000`.
- The SPA uses **no** `import.meta.env` values and calls `/api` relatively, so the web bundle needs no build-time API URL — same-origin through Caddy is sufficient.
- The API's routes are all under `/api/*` **except**: `POST /webhooks/sendgrid/:pathToken`, `GET /unsubscribe/:token`, and `/healthz` + `/readyz` from plan 14-01. All four must be proxied.
- Every workspace's `build` is `tsc -p tsconfig.json` emitting to `dist/`; `apps/api` and `apps/worker` both have `start: node dist/server.js`. `apps/web`'s `build` is `tsc --noEmit && vite build` emitting to `dist/`.
- `.nvmrc` pins **Node 26** for dev/CI, and STATE.md records the drizzle-kit CLI hanging under it. D-03 pins images to Node 22 LTS deliberately; deriving from `.nvmrc` would reintroduce that into production.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build context → image | Anything in the context can end up in a layer, permanently, including a secret deleted in a later layer |
| third-party GitHub Action → CI token + checked-out tree | An action runs with `packages: write` and full read of the repository |
| internet → Caddy | The single public entry point; whatever it proxies or serves is world-reachable |
| registry tag → deployed artifact | If a tag is mutable, "deploy SHA X" and "what actually ran" can differ |
