<objective>
Close DB-09: automatic backups with point-in-time recovery, using pgBackRest with an off-host S3-compatible repository encrypted by the tool's own repository cipher (D-05, D-06). `pg_dump` was ruled out in REQUIREMENTS.md for lack of PITR, and a backup that lives on the VPS it protects is explicitly not acceptable.

Purpose: this is the first disaster-recovery path this codebase has ever had. The single most consequential detail is that WAL archiving is executed by Postgres itself via `archive_command`, which means the pgBackRest binary has to exist inside the database container — a sidecar alone cannot archive WAL, and a configuration that looks complete while WAL is not being shipped gives PITR coverage of nothing.
Output: a Postgres image with pgBackRest installed, the repository configuration, a scheduled backup sidecar, the compose wiring, extended compose invariants, a backups runbook, and a blocking checkpoint for the first real backup.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VPS → S3-compatible object storage | The entire database leaves the host in this direction |
| object storage bucket → the internet | A misconfigured bucket exposes every row the platform has ever held |
| repository cipher passphrase → the ability to recover | Without it the repository is unreadable; with it alone the data is readable |
