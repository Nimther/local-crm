<objective>
Close DB-14 and the client half of DB-13 by construction (D-11): one `createPgPool()` factory in `packages/db` that wires the error handler, the TLS decision and an explicit size, every production pool site migrated onto it, and a CI-enforced guard that fails on any bare pool construction — the same single-definition move `@mega-crm/queue-core` made for Redis options in WRK-11. Purpose: DB-14's requirement is "все пулы имеют обработчик ошибок" — a property that decays the moment someone adds a ninth pool. A factory plus a lint gate turns it from a convention into an invariant. And RESEARCH.md Pitfall B is the specific trap here: a `?sslmode=require` in the DSN silently overrides any `ssl` object the code believes it configured, so "TLS looks configured in review" is not evidence.
Output: `packages/db/src/pool.ts`, ~13 migrated call sites, `scripts/lint-pg-pool-factory.mjs` wired into the CI static job, a TLS-serving dev Postgres, and a `pg_stat_ssl` assertion.
</objective>
