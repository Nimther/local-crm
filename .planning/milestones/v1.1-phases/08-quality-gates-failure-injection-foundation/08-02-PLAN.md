## Phase Goal

Any change to the send pipeline can be proven safe before it ships — CI blocks broken code, tests cannot touch the dev database, and every failure mode the audit names can be reproduced on demand.

This plan turns the tracer's hand-named database and two-condition guard into the real thing: per-workspace, per-run ephemeral databases created and destroyed by one script that behaves identically locally and in CI, with the destructive half of that script guarded from the inside.

## Artifacts this phase produces

- `createEphemeralDatabase(options)` and `dropEphemeralDatabase(databaseName, adminDsn)` exported from `packages/test-support/src/provision-db.ts`
- `buildEphemeralDatabaseName(workspace, runId)` (exported helper)
- `resolveAdminDsn()` (module-internal helper reading `TEST_ADMIN_DATABASE_URL`)
- Env var `TEST_ADMIN_DATABASE_URL` (admin/superuser DSN used only for CREATE/DROP DATABASE)
- Env var `GSD_TEST_RUN_ID` (optional run discriminator; falls back to a generated value)
- Database-name convention `mega_crm_test_<workspace>_<runId>`

<objective>
Implement the full fail-closed test-database contract: the complete four-row guard from SPEC R4, and an ephemeral-database provisioning module whose drop path physically cannot touch a non-test database. Wire both into `apps/worker`'s vitest `globalSetup` so the tracer's hand-named `mega_crm_test_worker` is replaced by a real per-run database with guaranteed teardown.

Purpose: SPEC R4 demands a hard failure rather than a graceful default (Pitfall 21), and the ephemeral-DB provisioner is the one place in this phase with enough privilege to destroy real data — the security threat register calls for the refusal to live inside the drop function itself.
Output: `provision-db.ts` with unit-proven refusal behavior, a `globalSetup` that provisions and tears down, and a guard covering all four SPEC acceptance rows.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provisioning script (admin role) → any Postgres database on the host | The only component in this phase holding `CREATE DATABASE`/`DROP DATABASE` privilege; a name-construction bug here destroys real dev data |
| Test process (app role) → tenant data under RLS | Handing tests a superuser DSN would silently disable every RLS assertion in the existing 85-file backend suite |
| Caller → `dropEphemeralDatabase` | A validation living at the call site rather than inside the function is bypassable by the next caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-02-01 | Tampering | `dropEphemeralDatabase` | critical | mitigate | Prefix + `^[a-z0-9_]+$` allow-list validated as the first statement of the function body, before any `Pool` construction and before any SQL interpolation; unit-proven against `mega_crm`, `postgres`, empty string and a quote-injection payload |
| T-08-02-02 | Elevation of Privilege | DSN returned to tests | high | mitigate | `createEphemeralDatabase` returns a DSN under `mega_crm_app` (NOSUPERUSER, NOBYPASSRLS per `docker/init-app-role.sql`); the admin DSN never leaves the provisioning module |
| T-08-02-03 | Tampering | SQL identifier interpolation in CREATE/DROP DATABASE | high | mitigate | Database names cannot be passed as bind parameters in DDL, so a local `quoteIdentifier` doubles embedded double quotes and the allow-list rejects any name containing a quote in the first place |
| T-08-02-04 | Denial of Service | Leaked ephemeral databases exhausting the dev Postgres | low | mitigate | `globalSetup` returns a teardown function (runs on failure too) and `createEphemeralDatabase` issues `DROP DATABASE IF EXISTS` before creating |
| T-08-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new package is installed by this plan — `pg` was already declared in the workspace manifest by 08-01 |
</threat_model>
