## Phase Goal

Any change to the send pipeline can be proven safe before it ships — CI blocks broken code, tests cannot touch the dev database, and every failure mode the audit names can be reproduced on demand.

08-11 set the threshold one percentage point above what the suite achieved. This plan closes that gap the only legitimate way.

## Artifacts this phase produces

- `packages/kms/vitest.config.ts`, `packages/kms/src/__tests__/envelope.test.ts`, `test` script in `packages/kms/package.json`
- `packages/tenant-context/vitest.config.ts`, `packages/tenant-context/src/__tests__/tenant-context.test.ts`, `test` script in `packages/tenant-context/package.json`

<objective>
Add targeted tests to the two packages that carry the highest-consequence untested code in this repository — tenant key encryption and the Row-Level-Security context — and close the deliberate coverage increment with them.

Purpose: D-19 chose those two packages for the increment on purpose. `packages/kms` performs envelope encryption of every tenant's SendGrid key, and `packages/tenant-context` sets the session variable that every RLS policy in the schema reads. Both are executed constantly by `apps/api`'s tests and neither has a single test of its own asserting what it does.
Output: two new test suites and a green coverage gate reached without touching the threshold.
</objective>
