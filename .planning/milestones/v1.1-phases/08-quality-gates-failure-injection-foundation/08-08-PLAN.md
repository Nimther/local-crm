## Phase Goal

Any change to the send pipeline can be proven safe before it ships — CI blocks broken code, tests cannot touch the dev database, and every failure mode the audit names can be reproduced on demand.

Three of the five audit-named failure modes land here. The two that need a real OS process or a real container restart are 08-12 and 08-13.

## Artifacts this phase produces

- npm scripts `failure:429`, `failure:timeout`, `failure:reset`
- `apps/worker/src/test/failure-fixtures.ts` exporting `fakeSendMail`, `countingSendMail`, `throwingSendMail`, `freshWorkspaceId`, `connectFixtureSendgridKey`, `createFixtureCampaign`, `createFixtureContact`, `sendsStatusFor`, `sendsRowCountFor`
- Test directory `apps/worker/src/queues/__tests__/failure-injection/`

<objective>
Turn three of the five audit-named failure modes into single commands with asserted outcomes, built on the `ProcessSendJobDeps.sendMail` seam that has existed since Phase 4 — and assert the behavior the system has TODAY, not the behavior Phase 11 will give it.

Purpose: QG-06 is a hard blocker for Phase 11. The delivery state machine cannot be safely changed without a harness that can reproduce these modes on demand. Asserting a future `'reconciling'` outcome that no code produces yet would make the harness red from birth and useless as a Phase 11 baseline.
Output: three npm scripts, each independently runnable, each asserting database state.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Failure scenario → the real SendGrid API | `packages/delivery-core/src/send-mail.ts` hardcodes the SendGrid endpoint; any scenario that reaches it would send real mail from a tenant's account and burn their domain reputation |
| Injected fake → the DI seam | Injecting anything beyond `sendMail` would mean the harness is testing the harness rather than the production dispatch path |
| Harness assertions → future state-machine changes | Asserting a state the current code cannot produce makes the harness red from birth, and a permanently-red harness is deleted rather than fixed |
