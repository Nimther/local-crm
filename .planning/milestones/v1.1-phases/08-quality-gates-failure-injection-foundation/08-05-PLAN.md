## Phase Goal

Any change to the send pipeline can be proven safe before it ships — CI blocks broken code, tests cannot touch the dev database, and every failure mode the audit names can be reproduced on demand.

This plan is the machine half of expand/contract discipline. The written half — the binding rule text in `CONVENTIONS.md` — lands in 08-17.

- Fixture directory `tools/migration-fixtures/` (4 files)
- `packages/test-support/src/__tests__/migration-lint.test.ts`

<objective>
Write the migration linter that will stop Phase 11 from adding `'reconciling'` to `send_status` and using it in the same transaction, and that forces any deliberately destructive DDL to carry a visible, reason-bearing marker on the statement itself.

Purpose: Postgres refuses to let a freshly-added enum value be used inside the transaction that added it, and this repo runs each migration file as one `client.query(sql)` call — so a single file doing both is a guaranteed runtime failure at deploy time, discovered in production rather than in review. DB-08 exists to catch it in CI, before Phase 11 needs it.
Output: a dependency-free Node linter, proven to fail on two fixture files of both violation kinds and to pass on all 38 real migrations.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration author → production schema | A single SQL file that both adds an enum value and uses it fails at deploy time with a Postgres error, after the deploy has already started |
| Migration author → existing production data | Unmarked destructive DDL (dropped column, NOT NULL added to a populated table) silently destroys or blocks on real rows |
| Marker comment → suppression scope | A file-level marker would blanket-suppress every destructive statement in the file, which is the pattern D-06/D-31 exist to forbid |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-05-01 | Denial of Service | Enum value added and used in one migration file | high | mitigate | `checkEnumAddValueSameFile` reports the violation and the CLI exits 1; the rule is proven by `tools/migration-fixtures/bad-enum-same-file.sql` and is the guard that protects Phase 11's `'reconciling'` addition |
| T-08-05-02 | Tampering | Unmarked destructive DDL reaching production | high | mitigate | `checkDestructiveDdl` flags `DROP COLUMN` and `ADD COLUMN ... NOT NULL` without `DEFAULT` unless the immediately preceding line carries a reason-bearing marker; two-violation fixture proves per-line detection |
| T-08-05-03 | Tampering | Blanket suppression via a file-header marker | medium | mitigate | The marker is accepted only on the immediately preceding non-blank line, and only with a non-empty reason; both constraints are unit-asserted |
| T-08-05-04 | Input Validation | Linter parsing arbitrary SQL file contents | low | accept | Input is trusted repo content read from disk with no evaluation; comments are stripped textually and nothing is executed |
| T-08-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed; the linter uses only `node:fs` and `node:path` |
