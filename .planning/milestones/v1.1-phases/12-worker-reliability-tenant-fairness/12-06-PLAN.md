<objective>
Rewrite the segment sweep as a bounded, checkpointed, resumable walk (WRK-05, WRK-06, D-09).

Purpose: the sweep today loads every matching contact for every live segment-triggered flow into memory in one transaction, on a 15-minute repeat, with no cursor and no page bound — the largest known unbounded-memory path in the worker. This plan splits discovery from the per-flow walk (mirroring campaign-scheduler to campaign-kickoff), pages on the contact id with a per-page statement timeout, and commits the resume cursor in the same transaction as that page's enrollment work so a kill between pages is exactly resumable by construction. The one clause that must not be copied from `recipient-snapshot.ts` is its permanent cursor: that cursor is a one-shot freeze, whereas this sweep is perpetual, so a cursor that never resets would silently skip any contact inserted behind it between ticks (Pitfall 3).
Output: a checkpoint table and module, a split discovery/walk pair of workers, and a kill-resume scenario in the failure-injection suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cross-workspace discovery scan → per-tenant work | The scan role sees every tenant's flows; everything after discovery must drop back to tenant scope |
| worker memory → contact volume | An unbounded result set is a self-inflicted availability risk at the platform's target contact volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-06-01 | Elevation of Privilege | sweep discovery scan | high | mitigate | `findLiveSegmentTriggeredFlows` is unchanged: it runs through the dedicated scan role with its narrowed select-only policy, and every subsequent read and write re-enters tenant-scoped context. The new checkpoint table grants the scan role nothing, so the walk cannot read another tenant's cursor. |
| T-12-06-02 | Denial of Service | unbounded per-flow query | high | mitigate | Pages are limited to `SWEEP_PAGE_SIZE` under a per-page statement timeout, the stale-snapshot cleanup deletes in bounded batches, and one job is bounded by `SWEEP_FLOW_JOB_BUDGET_MS`. |
| T-12-06-03 | Tampering | walk job payload | medium | mitigate | Both payloads are validated against their zod schema with a literal version field; an unrecognised version defers rather than executing against a mismatched shape. |
| T-12-06-04 | Information Disclosure | checkpoint rows across tenants | high | mitigate | The checkpoint table enables and forces row-level security with the fail-closed workspace predicate, so an unscoped query raises rather than silently returning another tenant's cursor. |
| T-12-06-05 | Repudiation | a silently skipped contact | medium | mitigate | The cursor resets on walk completion and a scenario case asserts a contact inserted behind the old cursor position is enrolled by the following walk. |
</threat_model>
