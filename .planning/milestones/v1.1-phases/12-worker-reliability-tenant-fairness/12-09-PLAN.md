<objective>
Replace the keep-forever failed-job retention with a bounded per-queue age (WRK-09), now that terminal failures are durably recorded elsewhere.

Purpose: roughly ten queues currently keep failed jobs indefinitely, which grows Redis without bound. That setting exists for a reason — losing a terminal failure silently is worse than the growth — so the ordering matters and is causal, not stylistic: the dead-letter writer must already be attached to every queue before any retention is shortened, or a job could age out of the Redis failed set before it was ever recorded (Pitfall 7). Plans 12-07 and 12-08 established that precondition; this plan is the last step. Retention stays a per-queue parameter of the shared factory, and the queue that deliberately differs keeps its own policy (Pitfall 6).
Output: a bounded retention default, its rationale, and an invariant test proving no queue keeps failed jobs forever.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis failed set → durable record | Once retention is bounded, the Postgres record is the only lasting evidence of a terminal failure |
| shared factory → per-queue policy | A single retention constant applied everywhere would erase a deliberate exception |
