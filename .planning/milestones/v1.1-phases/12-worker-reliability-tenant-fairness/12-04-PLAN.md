<objective>
Wire the tenant+lane semaphore into all three dispatch paths in `send-dispatch.ts` so an over-cap send takes the same deferral route as an over-RPS send (WRK-02, D-01/D-02).

Purpose: this is the second trigger into the deferral path the tracer built. CONTEXT.md's shape is explicit — over-RPS and over-concurrency both route through `tenant_bucket`; the worker never stalls wholesale for a tenant-scoped reason, and only genuine provider backpressure may pause a worker. The slot is acquired before the SendGrid call and released in a `finally`, so a crash releases it only via lease expiry and a normal exit releases it immediately.
Output: slot acquisition and release at the campaign, test and flow dispatch sites, plus an integration test proving deferral, release-on-every-path and cross-tenant isolation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dispatch path → Redis semaphore | Slot state is external; a call that skips it dispatches uncapped |
| dispatch claim (Postgres) → deferral return | A deferral that forgets the claim strands a send row in dispatching |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-04-01 | Denial of Service | over-cap send stranding its dispatch claim | high | mitigate | The over-cap path releases the dispatch claim exactly as the existing rate-limited path does before returning, so a deferred send is re-claimable on redelivery rather than blocked until the reconciler's window. Asserted by the campaign and flow deferral cases. |
| T-12-04-02 | Denial of Service | slot never released after an unusual exit | high | mitigate | Release sits in a `finally` spanning every return of each dispatch branch, covering the success, provider-rejection, 4xx, thrown-`sendMail` and RPS-deferral exits; lease expiry from 12-03 is the crash-time backstop. Asserted by five release-path cases. |
| T-12-04-03 | Elevation of Privilege | lane derived from caller-supplied data | medium | mitigate | The lane is derived from the validated job kind by `laneForSendJobKind`, never passed in as a separate argument, so a job payload cannot select a different tenant's or lane's slot pool. |
| T-12-04-04 | Information Disclosure | semaphore keys embedding a workspace id | low | accept | Redis keys already embed the workspace id for the RPS bucket; the semaphore adds no new identifier class and Redis is not a tenant-reachable surface. |
</threat_model>
