<objective>
Make terminal job failures durable and observable in Postgres (WRK-10, D-07) and give every worker one shared error-listener helper (WRK-08).

Purpose: there is no `error` or `failed` listener anywhere in `apps/worker` today, and `removeOnFail` is set to keep failed jobs forever across roughly seven queues precisely because losing them would be worse. D-07 replaces that with a durable Postgres record so retention can then age out freely — which is why the writer must be wired everywhere **before** any retention is shortened (Pitfall 7's causal ordering; 12-09 is the plan that depends on it). For send jobs the sends ledger remains the terminal truth; the dead-letter table's chief value is the lanes without a ledger — ingest, webhooks, CSV import and flow ticks — where a silently aged-out job is lost data.
Output: the `dead_letter_jobs` and `dead_letter_alert_state` tables, the redacting terminal-failure writer, and the shared listener helper in `queue-core` with an injected hook.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| job payload → durable Postgres record | Job payloads carry contact data and provider credentials; persisting them verbatim would create a new exposure surface |
| worker event listener → process | An exception in a listener is an unhandled rejection that kills every worker in the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-07-01 | Information Disclosure | dead-letter payload snapshot | high | mitigate | Every snapshot passes through the redaction package's scrub before the insert, and the writer test asserts a representative payload holding an email address, a provider API key and a bearer token is stored with all three censored. |
| T-12-07-02 | Denial of Service | listener or writer exception | high | mitigate | The writer catches and logs database errors instead of rethrowing, and the listener catches hook rejections; neither can become the unhandled rejection that terminates the worker process. |
| T-12-07-03 | Elevation of Privilege | scan-role access to the dead-letter table | medium | mitigate | The migration grants the cross-workspace scan role no privileges on either new table, and the header comment records that the tables are platform-scoped with no tenant-facing read path. |
| T-12-07-04 | Repudiation | duplicate or missing terminal records | medium | mitigate | The unique constraint on the queue-name and job-id pair plus the conflict-update clause make repeated terminal writes idempotent, and the terminal gate keeps mid-retry failures out of the table entirely. |
</threat_model>
