<objective>
Replace the worker-wide `worker.rateLimit()` stall with a tenant-scoped deferral for the `tenant_bucket` cause (WRK-01), through one shared helper both send lanes call.

Purpose: This is the phase's headline capability and its tracer. One tenant hitting its own ceiling must not stop the worker from draining every other tenant's jobs. Phase 11 already shipped the `cause: "tenant_bucket" | "provider_backoff"` discriminator on `SendJobResult` at all six `rate_limited` return sites, so both ends of the path already exist — this plan wires the correct BullMQ mechanism between them. WRK-02's concurrency cap later becomes a second trigger into this same proven path ("one deferral flow, two triggers").
Output: `tenant-deferral.ts`, both send-worker wrappers rewired, and a runnable end-to-end test proving one tenant's deferral does not stall the lane.
</objective>

## Assumption-Delta Decision (detector fired: `pluralization`)

The `assumption-delta` detector fired on this phase (`kind: pluralization`, term "another", from the WRK-02 open-decision text "…occupy worker slots ahead of another tenant's small batch").

- **Noun now primary:** `(workspace_id, lane)` is the primary identity for **worker-slot fairness accounting**. Before this phase, throttling identity was `workspace_id` alone.
- **Decision:** `promote`. Every new fairness mechanism in this phase is keyed on the `(workspace_id, lane)` pair from the start (D-02); no tenant-only concurrency key is introduced alongside it.
- **Rationale:** the pre-existing tenant-only RPS bucket is *not* a demoted duplicate of the same noun — it models the tenant's SendGrid **account** ceiling, which is genuinely per-tenant because each tenant brings its own API key. Worker-slot occupancy is genuinely per-lane. Two different ceilings, two correctly different keys; both are documented in `SPECIFICATION.md` §5 by 12-04.
- **Invariant test (accepted):** 12-05 asserts that a tenant saturating one lane does not reduce that **same tenant's** throughput in the other lane — the check that goes red the moment a future phase collapses the key back to tenant-only.
