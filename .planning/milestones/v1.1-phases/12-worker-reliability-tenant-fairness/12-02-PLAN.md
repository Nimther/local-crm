<objective>
Create the `@mega-crm/queue-core` workspace package (D-10) and collapse every duplicated Redis-connection and job-option definition inside `apps/worker` into it (WRK-11, worker half).

Purpose: the duplication is wider than the phase's own scout enumerated. A repository scan finds the connection builder declared in six places across the two applications and the retry/backoff job-option shape declared in eleven. Phase 11's `apps/worker/src/queues/queue-options.ts` was written expressly to be absorbed here — its own doc comments name three of the copy sites. Retention must arrive as a per-queue parameter and never one baked-in shape: `flow-run-advance`'s differentiated policy is a deliberate precedent whose loss would reintroduce a shadowed-wake bug this project has already fixed once (Pitfall 6).
Output: the package, every worker-side duplicate removed, and the constants documented. The application side is finished by plan 12-11, which also lands the invariant test that guards both.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → Redis | Every BullMQ connection the worker constructs now resolves its options from one module |
| shared factory → per-queue policy | A factory that over-generalises would silently change a queue's retry or retention behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02-01 | Denial of Service | retention collapsed into one shape | high | mitigate | The factory requires retention as a parameter typed to the two known shapes, preserving flow-run-advance's completion policy; collapsing it would reintroduce the shadowed-wake bug this repository already fixed once. Asserted by the package's own tests including an expect-error case for an ad-hoc shape. |
| T-12-02-02 | Tampering | the deliberately divergent application-side Redis client | medium | mitigate | That client is explicitly excluded from the consolidation and named as a non-target in this plan's inventory; it is not a BullMQ connection and its own comment documents why its retry setting differs. |
| T-12-02-03 | Information Disclosure | Redis credentials in the moved builder | low | accept | The builder parses credentials from the process's own environment and returns them in an options object exactly as before; relocating the code changes no exposure surface and adds no logging. |
</threat_model>
