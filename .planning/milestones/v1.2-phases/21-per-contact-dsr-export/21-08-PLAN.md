<objective>
Close gap G-21-3: at 375px the contact card overflows the page (body
clientWidth 375 vs scrollWidth 1029), the Delete button renders outside the
visible viewport, and the inline export message starts off-screen.

Purpose: the diagnosis
(`.planning/debug/contact-card-narrow-viewport-overflow.md`) proved this is an
AND-gate defect across two layers, and that fixing the header alone
mathematically cannot clear the page overflow — a 256px fixed sidebar plus
64px of page padding plus the smallest header button already exceeds 375px.
The diagnosis handed the planner an explicit choice, and this plan settles it:
**make the shell responsive, do not re-scope the criterion.** The gap as the
user stated it is "no horizontal page overflow at 375px, message visible";
re-scoping the criterion to the content column would declare the gap closed
while the page still scrolls sideways.

Output: a responsive shell that hides the fixed sidebar below the `md`
breakpoint behind a drawer, a contact card header that wraps, and a Playwright
spec that measures the same numbers the tester measured.

Not a tracer-led plan: gap closure on an executed phase. The architecture is
proven; Task 1 supplies the fail-first evidence a tracer would otherwise
provide.
</objective>
