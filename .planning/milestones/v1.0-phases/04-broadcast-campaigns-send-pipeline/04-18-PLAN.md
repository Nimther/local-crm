<objective>
Close UAT Test 12: editing a segment referenced by a scheduled campaign shows no D-03 warning before saving. Per .planning/debug/segment-editor-d03-warning-missing.md this is NOT a recurrence of the 04-15 pageSize bug (that fix is verified effective) — it is the warning's client-side lifecycle in apps/web/src/features/segments/SegmentDetailPage.tsx:

- The referencing-campaigns `useQuery` runs once at mount; the app-wide QueryClient has `refetchOnWindowFocus: false` and no refetchInterval, so a mounted editor never refreshes the snapshot.
- `handleSave()` performs ZERO D-03 check — it validates only name/definition and mutates.
- Query errors are silently swallowed (no isError branch), rendering as "no warning".

So whenever the campaigns snapshot predates the scheduling event (the exact test-12 flow: campaign scheduled 23:48, segment saved 23:55 in the same mounted session), the warning deterministically never appears — including at the save click, where the UAT truth anchors it ("warns ... before you save changes").

Fix (as directed by the debug session):
1. Extract the D-03 decision into a pure helper and reuse it for BOTH the passive mount-time banner and a new save-time gate.
2. In handleSave, before mutate(), await a fresh refetch of the referencing-campaigns lookup; if a scheduled campaign references this segment, require an explicit confirm (an inline two-step confirm, or a confirm dialog) before committing.
3. Surface the query's isError as a muted note instead of rendering nothing.
4. Give the decision real automated coverage by standing up a minimal vitest unit lane in apps/web (vitest is already hoisted from api/worker — no new npm installs) and testing the pure helper.

Purpose: The marketer is warned at the moment it matters — the save — that they are about to change a scheduled campaign's audience (CAMP-05, D-03), and the logic is pinned by a test so it cannot silently regress.
Output: A pure save-gate helper, a save-time refetch+confirm gate and isError surfacing in the segment editor, a web unit-test lane, and unit coverage of the decision.
</objective>
