**As a** marketer, **I want to** send a broadcast to a segment through a throttled, idempotent, suppression-aware queue, **so that** my emails reliably reach inboxes via SendGrid Dynamic Templates with per-message unsubscribe and frequency-cap compliance.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> launch/schedule/settings API | Role-gated mutations; the client gate is UX only, the server gate is authoritative |
| test-send JSON textarea -> API | User-editable JSON crosses to the send worker |
| local datetime -> UTC | Timezone conversion must not drift the scheduled instant |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-08-01 | Elevation of Privilege | Member triggering launch/schedule/settings via the UI | high | mitigate | Client controls disabled+tooltip for Members AND the server routes are behind requirePermission("campaign","launch") (04-05) — the client gate is defense-in-depth only |
| T-04-08-02 | Tampering | malformed test-send JSON | low | mitigate | The textarea value is JSON-parsed + validated (testSendCampaignSchema) client- and server-side before enqueue; a parse error shows inline copy, not a crash |
| T-04-08-03 | Tampering | wrong scheduled instant from timezone mishandling | medium | mitigate | The datetime-local value is converted to a UTC ISO string with the resolved IANA zone shown to the user (D-06); the server stores/reasons in UTC only |
| T-04-08-04 | Tampering (XSS) | campaign/segment name in dialogs + breakdown | low | mitigate | React escapes text nodes; no dangerouslySetInnerHTML for campaign-supplied strings |
</threat_model>
