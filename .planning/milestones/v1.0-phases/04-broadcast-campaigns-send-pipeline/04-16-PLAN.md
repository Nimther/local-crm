<objective>
Close the shared root cause behind UAT Test 4 (test email never arrives) and UAT Test 5 (broadcast stuck at «0 отправленных»): the dev stack boots with two undocumented, unvalidated runtime dependencies missing, so every send job crashes and every kickoff job crashes — invisibly, because the API already returned 202 and vitest injects the missing values.

Two independent, individually-fatal gaps are fixed here (per the two debug sessions):

1. **Missing send-signing env vars.** `UNSUBSCRIBE_TOKEN_SECRET` and `PUBLIC_APP_URL` are read lazily inside packages/delivery-core/src/unsubscribe-token.ts and throw when unset. They appear in NO boot check: not in scripts/check-env.mjs, not in apps/api/src/env.ts, and the worker validates only REDIS_URL. Both vitest configs inject test-only defaults, so all 66 automated checks pass while every real dev send/kickoff crashes. Fix = fail-fast validation in all three boot paths (the code the executor CAN edit) plus a `user_setup` handoff for the .env / .env.example values (the files the executor CANNOT edit).

2. **Unapplied migrations with no bootstrap guard.** The dev DB was migrated only through 0016; migrations 0017–0019 were added by plans 04-06+ but `npm run dev` has no migrate step, so the campaign-kickoff worker's first query (`SELECT ... fan_out_complete`) throws `column "fan_out_complete" does not exist`. Fix = a `predev` migrate step so `npm run dev` always applies pending migrations first (this both prevents recurrence AND applies 0017–0019 on the user's next `npm run dev`).

This plan does NOT change delivery-core's lazy `getSecret()`/`buildListUnsubscribeUrl()` throws (they remain correct defense-in-depth); it adds the missing fail-fast layer ABOVE them so the failure surfaces at boot with a clear message, not per-job in the failed set.

Purpose: The send pipeline can actually dispatch — the marketer's test email and broadcast reach SendGrid instead of dying at token-signing, and a stale migration can never again strand a launched campaign at 0 sent.
Output: Fail-fast env validation in check-env.mjs + api env.ts + worker boot; a migrate-dev bootstrap script wired into predev; a user_setup handoff for the two .env values.
</objective>
