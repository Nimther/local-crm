## Phase Goal

**As a** recipient clicking an unsubscribe link, **I want to** land on a safe confirmation page, **so that** a tampered link cannot run script in my browser while I opt out.

<objective>
Close CR-01 (blocker, independent of the send pipeline). `unsubscribe.routes.ts:39` interpolates the raw, unvalidated `:token` route param directly into `<form action="/unsubscribe/${token}">` on the UNAUTHENTICATED public GET page, with `maxParamLength: 1024` (server.ts:35) giving ample payload room and NO `@fastify/helmet` registered anywhere — a textbook reflected XSS. This plan neutralizes the reflection two ways (strict token-format guard + HTML-attribute escaping) and adds defense-in-depth security headers via `@fastify/helmet` (already a dependency, never registered). WR-05 (missing helmet) is folded in here because it is the same file surface and directly compounds CR-01.

Purpose: a public, unauthenticated endpoint must not be an XSS vector; this is the highest-severity finding and must not block on the send pipeline.
Output: hardened GET/POST unsubscribe handlers + helmet CSP + an XSS regression test.
</objective>
