## Phase Goal (MVP user story)

**As a** marketer, **I want to** send a broadcast to a segment through a throttled, idempotent, suppression-aware queue, **so that** my emails reliably reach inboxes via SendGrid Dynamic Templates with per-message unsubscribe and frequency-cap compliance.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> campaign API | All mutations go through the session-authed API; the client never sees the tenant SendGrid key |
| campaign name/segment strings -> DOM | User-supplied text rendered in the list/badges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07-01 | Elevation of Privilege | Member seeing enabled launch/schedule controls | medium | mitigate | Launch/schedule controls render disabled with the Owner/Admin tooltip for Members (04-08 wires the action; this plan's builder only saves drafts, which Members may do — D-19) |
| T-04-07-02 | Tampering (XSS) | campaign name / segment name rendered in list | low | mitigate | React escapes text nodes by default; no dangerouslySetInnerHTML used for campaign-supplied strings |
| T-04-07-03 | Information Disclosure | tenant SendGrid template/sender data | low | accept | Only template ids/names and verified sender emails (already tenant-owned, non-secret) are fetched to the client via the server-side decrypt route; the key itself never leaves the API |
</threat_model>
