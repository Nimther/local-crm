<objective>
Create the data backbone and shared contracts for the entire send pipeline: four RLS-protected Postgres tables (`campaigns`, `campaign_recipients`, `sends`, `workspace_send_settings`), their Drizzle schema files and migrations, the shared Zod campaign request/response schemas, and the shared BullMQ queue-name constants + job-payload schemas every later plan in this phase imports.

Purpose: Every downstream plan (delivery-core, dispatch worker, campaign backend, kickoff worker, UI) reads or writes these tables and imports these constants — nothing else can be built until the schema exists and the migration is applied. This is the foundation the vertical send slice stands on (see Phase Goal).
Output: 4 schema files, 4 migrations (applied), campaign Zod schemas, extended queue schemas.
</objective>

## Phase Goal (MVP user story)

**As a** marketer, **I want to** send a broadcast to a segment through a throttled, idempotent, suppression-aware queue, **so that** my emails reliably reach inboxes via SendGrid Dynamic Templates with per-message unsubscribe and frequency-cap compliance.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
