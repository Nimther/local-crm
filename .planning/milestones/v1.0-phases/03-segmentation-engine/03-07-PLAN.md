<objective>
Make the tags condition user-reachable in the builder and close the silent-failure create flow, plus fix the two UI dead-ends (unreachable segments past page 1, infinite skeleton on a bad segment id). This is the web half of the failed truth "a user can build and save a segment from profile attributes (country, tags, custom properties)."

User-observable slice: after this plan a marketer can select «Теги» → «есть тег» → type a tag, save, and — if they instead click save on the untouched default row — they see a clear inline error rather than a button that appears to do nothing.

Purpose (gap closure): closes the tags-unreachable half of the failed truth (STANDARD_FIELDS omits tags despite full engine support, D-03/D-04) and the CR-01 client-side half (validateDefinition never checked attribute-field emptiness; the create mutation had no onError/error UI). Also closes WR-05 (list hardcodes page 1) and WR-06 (detail infinite skeleton), and IN-04 (validateDefinition duplicated across two pages). Addresses SEGM-01.
Output: a builder that can build every field the contract supports, a create flow that fails loudly, a paginated list, and a detail page that surfaces not-found.
</objective>
