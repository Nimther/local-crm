<objective>
Make the segmentation engine live and queryable over HTTP. Create the `segments` table (RLS-scoped) and its migrations, then build the evaluation repository (`count` / `listMembers` / `isMember`, all over the one compiled WHERE from `@mega-crm/segments-core`) plus segment CRUD, the distinct-event-name picker, and the Fastify `segments` module — including the live `POST /preview-count` endpoint with a DoS-bounding statement timeout.

Purpose: This is the end-to-end backbone: after this plan a user (or a curl) can create a segment, list segments, resolve members, and get an exact preview count for an unsaved definition — proving SEGM-01/02/03/04 at the API tier before any UI exists. The three-mode contract test makes SEGM-03's "identical membership" guarantee explicit.
Output: A migrated `segments` table with RLS, a registered `segments` API module, and green integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → segments API | Session-authed workspace members POST definitions and pagination params; the definition shapes SQL and the count query cost. |
| API → Postgres (RLS) | Every segment/count/member query must carry the per-transaction tenant GUC or it silently returns zero rows (or, if bypassed wrong, leaks). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Information Disclosure | segment.repository.ts (count/list/isMember/CRUD) | high | mitigate | Every query runs inside `withTenantTransaction` with `getWorkspaceId()`; `segments` table has FORCE ROW LEVEL SECURITY + `workspace_isolation` policy; no direct `pool.query`. Contract test + acceptance grep enforce no pool bypass. |
| T-03-04 | Denial of Service | POST /segments/preview-count | high | mitigate | `SET LOCAL statement_timeout = 2000ms` scoped to the preview-count query; Postgres 57014 mapped to a `{ degraded: true }` 200, bounding worst-case cost of a pathological definition regardless of condition count (D-08). |
| T-03-05 | Information Disclosure | segments.routes.ts auth | low | mitigate | `resolveWorkspaceMember` returns 404 (not 401/403) on unauthenticated / non-member / unknown-slug, so routes cannot be used as a workspace-enumeration oracle. |
| T-03-06 | Denial of Service | event-names.repository.ts | medium | mitigate | Loose-index-scan recursive CTE instead of `SELECT DISTINCT name FROM events` (1900x slower at 2M rows, Pitfall 2). |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new external packages this phase (RESEARCH Package Legitimacy Audit: N/A). Only the internal `@mega-crm/segments-core` workspace dep is added to apps/api. |
</threat_model>
