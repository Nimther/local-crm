</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → segments API (members/delete) | Member-list and delete requests are session-authed; membership rows are contacts that must never cross tenant boundaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-08 | Information Disclosure | GET /segments/:id/members rendering | high | mitigate | The member list is served by `listSegmentMembers` under withTenantTransaction/RLS (03-02, T-03-03); the detail page only renders rows returned for the caller's workspace via the 404-not-409 resolveWorkspaceMember gate. No cross-tenant id can be resolved. |
| T-03-11 | Tampering | DELETE /segments/:id (IDOR) | medium | mitigate | Delete goes through the same RLS-scoped `deleteSegment` (workspace_isolation policy); a segment id from another workspace resolves to a 404, never a cross-tenant delete. |
| T-03-10 | Information Disclosure | rendering segment name in delete dialog | low | accept | React escapes the interpolated name; rendered as a text node. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages this phase (alert-dialog/dropdown-menu already installed in Phase 1/2). |
</threat_model>
