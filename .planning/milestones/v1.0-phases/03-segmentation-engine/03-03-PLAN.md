<objective>
Deliver the marketer-facing capability: a segment builder where a user composes profile-attribute and behavioral conditions in two-tier AND/OR groups, watches a live match count update as they edit, and saves a named segment — reachable from a new "Сегменты" nav section. This is the first end-to-end user slice on top of the live 03-02 engine.

Purpose: Turns the API-only engine into something a marketer can use — SEGM-01 (build profile-attribute segments), SEGM-02 (add behavioral conditions), SEGM-04 (live count while building). Follows the Phase 2 contacts UI conventions and the 03-UI-SPEC contract exactly.
Output: A working create-and-save flow with live count, a minimal segments list, nav + routes, and a Playwright happy-path spec.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser builder → segments API | The definition is assembled client-side but the server (03-02 Zod + allow-list) is the security authority; the client cannot widen the operator/field allow-list. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | SegmentBuilder → preview-count / create | medium | mitigate | The builder only assembles the SegmentDefinition; all validation authority is server-side (03-02 `previewCountSchema`/`createSegmentSchema` + compiler allow-list). Client-side validation is UX-only and cannot bypass the server. |
| T-03-09 | Denial of Service | live-count request storm | low | mitigate | 300ms debounce + definition-as-queryKey coalescing on the client; the real bound is the server statement_timeout (T-03-04, 03-02). |
| T-03-10 | Information Disclosure | rendering segment name / recap | low | accept | React escapes interpolated text by default; the recap and name are rendered as text nodes, not HTML. |
| T-03-SC | Tampering | shadcn add popover command | low | accept | shadcn official registry only (copies component source, not an npm dependency); no third-party registry, no package-manager install to gate (RESEARCH: no new packages). |
</threat_model>
