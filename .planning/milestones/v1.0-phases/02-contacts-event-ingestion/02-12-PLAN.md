## Phase Goal

**As a** marketer importing a large CSV, **I want to** see a bad subscription-status value flagged in the preview, a broken/oversized upload reported as failed instead of a false success, and an import that cannot finish surfaced rather than spinning forever, **so that** I can trust the dry-run report and never believe a partial import succeeded.

<objective>
Close the CSV-pipeline robustness warnings on the import feature (these HARDEN already-satisfied CONT-02 — not re-claiming it per gap-contract rule 5, so `requirements` is intentionally empty):

- WR-05: `applyCsvRowMapping` writes the raw CSV cell into the typed `subscriptionStatus` via an untyped cast — an invalid value passes dry-run (counted in willCreate/willUpdate) then fails at apply time (dry-run/apply drift), and a CSV can set `suppressed` directly, bypassing the D-12 guard. Fix: validate in the shared mapper so dry-run and apply agree and suppressed is refused.
- WR-04: the upload route has no failure path — a malformed CSV that throws mid-stream 500s and strands the row in `uploaded`, and a truncated (>50MB) upload is silently imported partially and reported as success. Fix: wrap the streaming loop to set `status='failed'`, and check `data.file.truncated` (mark failed / 413). This also makes the schema's `failed` status actually reachable (IN-06).
- WR-03: when a row's error-marking UPDATE also fails, the error is swallowed and the row stays `pending` while the cursor advances past it; the final recount leaves status `applying` but the BullMQ job completes successfully, so nothing re-runs it. Fix: on `stillPending > 0` at recount, throw so the job fails (retryable — 02-10 configures queue retries), and don't advance the cursor past a row whose error-marking failed.

Vertical slice: failing tests first, then the shared mapper validation, the worker durability, and the upload failure path.

Purpose: the dry-run preview and completion report are CONT-02's core promise ("preview before applying" + "report of errors and duplicates"); silent drift, false success, and stuck-forever states break that trust.
Output: validated status mapping, a reachable failed state, a non-silently-stuck apply, and regression tests.
</objective>
