## Phase Goal

**As a** marketer, **I want to** remove a custom property and clear a standard field on a contact and have it actually save, **so that** the contact record reflects what I see on screen instead of silently keeping stale data behind a false success toast.

<objective>
Close CR-04 (verification gap on Success Criterion #1 / CONT-01, CONT-05): contact edits that DELETE a custom property or CLEAR a standard field are silently discarded server-side while the UI shows «Контакт обновлён». Root cause is a merge-vs-replace mismatch — `updateContact` merges `properties` (so a removed key is re-added) and the form drops emptied fields from the PATCH body entirely (so the repository's keep-existing fallback preserves the old value forever).

This is a complete vertical slice: the failing regression tests come first, then the server (schema + repository) is made to honor replace/clear semantics, then the form is made to send an explicit clear signal.

Purpose: A user-facing edit surface that cannot delete or clear a value — while reporting success — is shipping-blocking incorrect behavior.
Output: Property deletion and standard-field clearing both persist; Overview edits never wipe properties; regression tests that would have caught CR-04.
</objective>
