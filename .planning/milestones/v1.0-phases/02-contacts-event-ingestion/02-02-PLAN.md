<objective>
Build the browser UI for the contact base on top of the 02-01 API: a searchable/filterable/paginated contact list, a create/edit form with a custom-property editor and tag input, and a tabbed contact detail page — all following the Phase 2 UI-SPEC exactly (shadcn new-york/neutral, Russian copy, reserved accent/destructive usage, semantic status badges).

## Phase Goal

**As a** marketer, **I want to** build and maintain my contact base through the UI, CSV import, and a server-side API — while my product backend streams freeform behavioral events — **so that** my contacts are created and enriched in real time and every contact carries an accurate subscription status.

This plan completes the manual-CRUD vertical slice: after it a real marketer can create, find, edit and delete contacts (with custom properties and correct subscription status) in the browser — something they could not do after 02-01, which exposed the capability only at the API layer.

Purpose: The contact list, detail page and property editor established here are reused by CSV import (02-07 links into the same feature dir) and become the surface where the event feed (02-06) and full timeline (Phase 7) later appear.
Output: A working /w/:slug/contacts area wired to the 02-01 API, verified against the UI-SPEC.
</objective>
