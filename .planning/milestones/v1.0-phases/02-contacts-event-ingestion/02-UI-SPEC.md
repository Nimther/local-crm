# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Provenance note:** No interactive user round was available for this design-contract session. Every value in this document either (a) is inherited unchanged from `.planning/phases/01-workspace-foundation-team-access/01-UI-SPEC.md` — the established, already-implemented design system — or (b) is a prescriptive researcher decision for phase-2-specific screens (contacts, CSV import, event feed, API keys), made by extending Phase 1's exact conventions rather than inventing new ones. Revise by re-running `/gsd-ui-phase 2` if any default should change.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 1, no changes:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding |
| sm | 8px | Gaps between form label and input, inline button groups, event-feed timestamp-to-text gap |
| md | 16px | Default gap between form fields, card inner padding (compact), custom-property row gap |
| lg | 24px | Card padding, gap between form sections, CSV wizard step spacing |
| xl | 32px | Gap between page header and content, gap between contact list toolbar and table |
| 2xl | 48px | Contact-list table row height (comfortable scan density at high row count) |
| 3xl | 64px | Page-level top/bottom margins on settings pages (API keys page) |

Exceptions: **none.** Tailwind classes only (`p-1/2/4/6/8/12/16`, `gap-1/2/4/6/8`), no arbitrary `p-[Npx]` values.

## Typography

Exactly 4 sizes, 2 weights — identical to Phase 1, no new sizes/weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta | 14px (`text-sm`) | 400 regular | 1.5 |
| Body | 16px (`text-base`) | 400 regular | 1.5 |
| Heading (section / card title) | 20px (`text-xl`) | 600 semibold | 1.2 |
| Display (page title, big-number callouts) | 28px (`text-display` token) | 600 semibold | 1.2 |

Phase-2-specific usage of the existing roles:
- Label/meta (14px): contact table cell text, filter/sort labels, event-feed timestamps (`3 минуты назад`), custom-property key labels, API-key prefix/mask display (`font-mono` per Phase 1 convention).
- Body (16px): contact form field values, CSV dry-run summary body copy, event JSON payload (monospace `font-mono` at 14px when expanded — same convention as the masked SendGrid key).
- Heading (20px/600): section/card titles — «Контакты», «Импорт CSV», «API-ключи», «Информация о контакте», «Лента событий».
- Display (28px/600): page titles, and the CSV dry-run big-number summary (`98 500 будет создано`).

No new size is introduced for the dry-run summary numbers — reuse Display.

## Color

Identical palette to Phase 1 — no new hues, no gradients.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `neutral-50` (`--background`) | Page background, main content surface |
| Secondary (30%) | `neutral-100` `#F5F5F5`, `neutral-200` `#E5E5E5` borders | Table header row, card backgrounds, sidebar, input borders |
| Accent (10%) | `indigo-600` `#4F46E5` (`--primary`) | See reserved list below — nothing else |
| Destructive | `red-600` `#DC2626` (`--destructive`) | Destructive actions + error/blocked states only (see list) |

**Accent (`indigo-600`) reserved exclusively for (extends Phase 1's list with this phase's screens):**
1. Primary CTA button per screen (one per screen max): «Добавить контакт», «Импортировать CSV», «Применить импорт», «Создать API-ключ»
2. Active tab in the contact-detail Tabs component (Overview / Свойства / События)
3. CSV import progress bar fill (`Progress` component) — transient, not a persistent surface
4. Focus rings (`--ring`), same as Phase 1
5. Checked/selected states of checkbox, radio-group, select — same as Phase 1

**Destructive (`red-600`) reserved exclusively for (extends Phase 1's list):**
1. «Удалить контакт» button + its confirmation dialog
2. «Отозвать API-ключ» button + its confirmation dialog
3. Inline form validation error text/borders (e.g. email uniqueness conflict)
4. CSV row-level error indicators in the dry-run/report table
5. **Suppressed** subscription-status badge (bounce/spam-complaint state) — same precedent as Phase 1's SendGrid error badge

**Semantic status colors (badges only, never general UI — extends Phase 1's precedent):**
- Subscription status **subscribed**: `green-600` `#16A34A` on `green-50` (same green as Phase 1's «Активен» SendGrid badge)
- Subscription status **unsubscribed**: `neutral-500` on `neutral-100` (same neutral as Phase 1's pending-invite badge)
- Subscription status **suppressed**: `red-600` `#DC2626` on `red-50` (destructive, per list above)
- CSV import row status: «создан»/«обновлён» = `green-600`; «пропущен» = `neutral-500`; «ошибка» = `red-600`
- API key status: «Активен» = `green-600` on `green-50`; «Отозван» = `neutral-500` on `neutral-100`

No gradients. No additional hues. No charts in this phase.

## Copywriting Contract

All UI copy is **Russian** (per Phase 1 convention — project working language). Sentence case, address the user with «вы» (lowercase), no exclamation marks.

### Primary CTAs (verb + noun, one per screen)

| Screen | Primary CTA |
|--------|-------------|
| Contact list | «Добавить контакт» |
| Contact quick-create dialog | «Создать контакт» |
| Contact detail (edit mode) | «Сохранить изменения» |
| CSV import — upload step | «Загрузить файл» |
| CSV import — mapping/preview step | «Проверить файл» (runs dry-run validation) |
| CSV import — after dry-run | «Применить импорт» |
| API keys page | «Создать API-ключ» |
| API key create dialog | «Создать ключ» |

### Empty states

| Element | Copy |
|---------|------|
| Contact list, no contacts yet | Заголовок: «Пока нет ни одного контакта» · Тело: «Добавьте контакты вручную, импортируйте CSV или начните отправлять события через API — контакты появятся автоматически.» · CTA: «Добавить контакт» |
| Contact detail, event feed empty | Заголовок: «Событий пока нет» · Тело: «Как только ваш бэкенд отправит первое событие через Event API, оно появится здесь.» (ссылка на документацию API-ключей) |
| CSV imports, no history yet | Заголовок: «Импортов ещё не было» · Тело: «Загрузите CSV-файл, чтобы добавить контакты пакетом.» · CTA: «Загрузить файл» |
| API keys, none created yet | Заголовок: «API-ключей пока нет» · Тело: «Создайте ключ, чтобы ваш бэкенд мог отправлять контакты и события через API.» · CTA: «Создать API-ключ» |

### Error states (problem + next step, never a bare code)

| Case | Copy |
|------|------|
| Email already used by another contact (D-07 uniqueness check) | «Этот email уже используется другим контактом. Укажите другой адрес или найдите существующий контакт.» |
| External_id already set, attempted edit (D-06 immutability) | Field shown read-only with helper text: «external_id нельзя изменить после установки — это постоянный идентификатор контакта.» |
| Attempt to un-suppress from UI (D-12) | Tooltip on disabled control: «Статус «в списке подавления» нельзя снять вручную — так мы защищаем репутацию отправки. Это происходит только автоматически.» |
| CSV file wrong type / unreadable | «Не удалось прочитать файл. Загрузите CSV в кодировке UTF-8 или Windows-1251.» |
| CSV file too large | «Файл превышает допустимый размер. Разделите его на несколько файлов меньшего размера и загрузите по очереди.» |
| CSV dry-run found errors | Inline in summary: «{N} строк с ошибками — их можно скачать, исправить и загрузить повторно.» (never blocks applying the valid rows) |
| API key creation failed | «Не удалось создать ключ. Попробуйте ещё раз — если ошибка повторится, обновите страницу.» |
| Generic server error | «Что-то пошло не так. Попробуйте ещё раз — если ошибка повторится, обновите страницу.» (same as Phase 1) |

### Destructive confirmations

| Action | Confirmation copy |
|--------|-------------------|
| Удаление контакта | AlertDialog: «Удалить контакт «{email или имя}»?» · Тело: «Контакт и все его события будут удалены безвозвратно. Если контакт был отписан или в списке подавления, письма ему не будут отправляться повторно даже после нового импорта.» · Кнопки: «Удалить контакт» (red-600) / «Отмена». |
| Отзыв API-ключа | AlertDialog: «Отозвать ключ «{имя ключа}»?» · Тело: «Любые запросы к Event API и Contacts API с этим ключом перестанут приниматься немедленно. Это действие нельзя отменить.» · Кнопки: «Отозвать ключ» (red-600) / «Отмена». |

### System copy notes

- Toasts (sonner): успех — «Контакт создан», «Контакт обновлён», «Контакт удалён», «Импорт запущен», «Импорт завершён», «Ключ создан», «Ключ отозван» — существительное + глагол-результат, без восклицательных знаков (same convention as Phase 1).
- API key secret shown once (D-22): Dialog after creation — «Скопируйте ключ сейчас. Мы не покажем его снова.» + monospace secret field + «Скопировать» button; closing the dialog without copying still keeps the key valid (only the *view* is one-time, not the key itself) — copy must make this explicit: «Ключ уже активен — если вы не скопируете его сейчас, просто создайте новый.»
- Masked API key list display (mirrors Phase 1's SendGrid-key mask pattern): `mcrm_a1b2…9f3k`, status badge, «Отозвать» action.
- Custom property editor (Claude's Discretion item, CONTEXT.md): key/value row list under an «Свойства» section — «Добавить свойство» adds a row with a key input (autocomplete suggestions from the property registry) + a type-aware value input (text/number/checkbox/date-picker driven by the registry's observed type, defaulting to text for unknown keys); each row has a remove (×) icon button. Helper text under the section: «Свойства подсказываются на основе данных из API, событий и предыдущих импортов.»
- Tag input: chip-style — existing tags render as removable `Badge` components inline with an input for adding new ones (comma or Enter to commit), reusing `badge` + `input`, no new component needed.
- CSV column mapping row: source column name (from file header) → target field select (`select` component, options = standard fields + known registry properties + «Создать новое свойство…» per D-19) — «Создать новое свойство…» opens an inline text input for the new property's name.
- CSV dry-run summary (D-17): three Display-sized (28px) stat numbers side by side — «Будет создано», «Будет обновлено», «Ошибок» — each in its own compact card, error count in red-600 if > 0.
- CSV report (D-18): on-screen summary (same three stats + «Пропущено» if skip-duplicates policy chosen) + «Скачать CSV с ошибками» link/button (only shown if errors > 0).
- Event feed row (D-14): icon (lucide `Activity`) + event name (14px/600) + relative timestamp (14px/400, muted) + expandable chevron; expanding reveals the JSON payload pretty-printed in `font-mono` 14px inside a `Collapsible`.

Interaction rules (extends Phase 1's, unchanged principles):
- Every mutating button gets a disabled + loading state during the request; no double-submit.
- Role gating: API-key management and contact delete are hidden (not disabled-with-tooltip) for roles that lack permission, mirroring Phase 1's D-17–D-19 convention; server remains the enforcement layer.
- Focus visible on all interactive elements (accent ring). Dialogs trap focus, close on Esc.
- CSV import is navigable-away-and-back (D-16): the import-progress screen must be re-enterable from the CSV import history list, polling the same status endpoint.
- The suppressed subscription-status control is **read-only in the UI** (D-12): render as a disabled `radio-group` option / static badge with a tooltip, never a clickable control that could appear actionable.
