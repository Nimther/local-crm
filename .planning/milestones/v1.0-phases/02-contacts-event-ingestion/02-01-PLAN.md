<objective>
Establish the contact data model and the session-authenticated CRUD backend that the marketer's UI (02-02) drives: a `contacts` table with standard fields, tags, freeform JSONB properties and a 3-state subscription status; a `workspace_suppressions` compliance list; a `workspace_property_registry` for auto-discovered custom properties; and a tenant-scoped repository + Fastify routes implementing create/read/update/delete with the identity, uniqueness, suppression and subscription rules from CONTEXT.md.

## Phase Goal

**As a** marketer, **I want to** build and maintain my contact base through the UI, CSV import, and a server-side API — while my product backend streams freeform behavioral events — **so that** my contacts are created and enriched in real time and every contact carries an accurate subscription status.

This plan delivers the first working vertical slice end-to-end at the API layer: after it, a user (proven by integration tests) can CRUD contacts with custom properties and a correct 3-state subscription status. The browser UI arrives in 02-02.

Purpose: Contacts are the spine of every later phase (segmentation, campaigns, flows, analytics); the identity + subscription + suppression rules established here are consumed by the API upsert (02-04), event ingestion (02-06), CSV import (02-07), the pre-send filter (Phase 4) and webhook suppression (Phase 5).
Output: Drizzle schema + committed RLS migration + shared Zod schemas + tenant-scoped repository + session-authed CRUD routes, all green under Vitest integration tests.
</objective>
