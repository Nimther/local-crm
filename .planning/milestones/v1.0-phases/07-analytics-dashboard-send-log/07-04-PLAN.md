## Phase Goal

**As a** marketer, **I want to** see end-to-end email performance — per campaign, per flow step, per contact, and across my whole workspace, down to the status of every individual message — **so that** I can tell what is working and always answer why a contact did or did not receive an email.

This plan delivers per-flow-step metrics (ANLT-02): a complete vertical slice from a GROUP-BY read over flow_run_steps + sends through a new analytics endpoint to both the canvas node badges and a comparison table tab, so a marketer sees which step underperforms.

## Artifacts this phase produces

- `flow-analytics.repository.ts` (`getFlowNodeAnalytics(flowId)`) and `flow-analytics.routes.ts` (`GET /api/workspaces/:slug/flows/:id/analytics`)
- `FlowAnalyticsTable` component (fourth FlowDetailPage tab)
- A `metrics` badge-overlay extension to `NodeShell`/nodeTypes and a metrics prop threaded through FlowCanvas

<objective>
Add a flow-analytics endpoint that aggregates flow_run_steps by node_id across all versions — distinct-contact pass counts for every node, plus send/delivered/opened/clicked/bounced for send nodes joined on sends(flow_run_id, node_id) — then surface it both as read-only canvas node badges (D-03) and as a comparison «Аналитика» table tab (D-03/D-05).

Purpose: A marketer identifies the underperforming step of a flow both in-context on the graph and as a sortable list, including nodes removed from the live version.
Output: A tenant-safe flow-analytics endpoint plus canvas badges and a table tab, driven by one response keyed by nodeId. Reads flow_run_steps + sends directly (both scoped to one flow; flow_run_steps is not partitioned) — no rollup table, honoring D-08b which targets the workspace-wide dashboard, not per-flow reads.
</objective>
