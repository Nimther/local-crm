<objective>
Close verification gap 2 (ANLT-04, SC4 / code-review CR-01): `workspace_daily_rollup.opened_count`/`clicked_count`/`bounced_count` are written by two paths with conflicting semantics. The incremental webhook path (`webhook-events.worker.ts`) increments on EVERY genuinely-new open/click event (repeat-event count) and increments `bounced_count` once per bounce/drop/spam terminal; the reconciliation worker (`analytics-reconciliation.worker.ts`, runs every ~3 min and overwrites the row) counts UNIQUE sends first-opened/clicked that day and folds all non-delivery terminals into one per-send count. The dashboard's «Открыто»/«Клики» trend and KPI values therefore oscillate between the two definitions on every reconcile tick, and open rate can transiently exceed 100%.

Fix by adopting the unique-send semantic in the incremental path (the cheaper, ≤100% option per CR-01, matching the reconciliation backstop and the campaign counters): gate the rollup open/click increment on the `justSet` first-write gate exactly like the `delivered` case, and gate the rollup+campaign `bounced_count` increment on the send not already having another non-delivery terminal fact. Keep `sends.open_count`/`click_count`'s own unconditional per-event repeat counter untouched. Add the currently-missing dual-write invariant regression test.

Purpose: The workspace dashboard's open/click/bounce trends become stable, well-defined numbers a marketer can trust across reconciliation cycles.
Output: A regression test proving the two writers agree, plus the gated increments that make them agree.
</objective>
