## Phase Goal

**As a** marketer, **I want to** see end-to-end email performance — per campaign, per flow step, per contact, and across my whole workspace, down to the status of every individual message — **so that** I can tell what is working and always answer why a contact did or did not receive an email.

This plan delivers the contact activity timeline (ANLT-03): a complete vertical slice from a UNION-ALL read query through a new analytics API route to the evolved ContactEventFeed UI, built on the status-history table and open/click counters from 07-01.

## Artifacts this phase produces

- `apps/api/src/modules/analytics/` module with `registerAnalyticsRoutes` aggregator (index.ts), `timeline.routes.ts`, `timeline.repository.ts`
- `GET /api/workspaces/:slug/contacts/:id/timeline` endpoint returning unioned, collapsed timeline rows
- Evolved `ContactEventFeed` unified timeline UI with a record-type filter

<objective>
Create the analytics API module and its contact-timeline endpoint (a UNION ALL over events + sends + subscription_status_history + flow_runs, collapsed via sends.open_count/click_count for «×N»), then evolve ContactEventFeed from an events-only feed into the unified chronological timeline with a record-type filter.

Purpose: A marketer opens a contact and sees the full story — every event, every email and its opens/clicks, every subscription-status change, and every flow entry/exit — in one place (D-10/D-12), answering "why did this contact get / not get this email."
Output: A new analytics module registered in server.ts, a tenant-safe timeline endpoint, and the unified timeline UI.
</objective>
