<objective>
Close the single remaining Phase 07 verification gap (WR-02): the send-log «Кампания / цепочка» selector keys cmdk's `CommandItem` selection identity by the campaign/flow display NAME (`CampaignFlowFilter.tsx` lines 83 and 100), not by id. cmdk (v1.1.1, confirmed in `apps/web/package.json`) uses `value` as each item's internal identity for filtering, highlight, and keyboard selection — duplicate `value`s collide and the first match wins. Because `duplicateCampaign` (`apps/api/src/modules/campaigns/campaign.repository.ts:318-343`) and `duplicateFlow` (`apps/api/src/modules/flows/flow.repository.ts:550-580`) copy the source name verbatim, two identically-named items is a routine result of the app's own «Дублировать» action — so selecting the second silently filters the send log by the first one's id, undermining per-campaign accountability.

Fix per 07-REVIEW.md WR-02: make the cmdk `value` unique by appending the id while keeping the name substring-searchable, and add a deterministic regression test.

Purpose: Restore correct per-campaign / per-flow send-log filtering when duplicate names exist, closing the last gap (8/9 → 9/9 must-haves).
Output: A unique cmdk identity for every selector item, a pure `sendTargetItemValue` helper, and a regression test exercising duplicate names.

Scope discipline: Frontend-only (`apps/web`); zero backend/schema changes; zero new dependencies. Other 07-REVIEW.md findings (WR-01, WR-03..WR-08, IN-01..IN-09) are explicitly OUT of scope for this round.
</objective>

## Phase Goal (MVP user story — scoped to this gap)

**As a** marketer who filters the send log by campaign or flow, **I want to** select the intended entity even when two share the same name (a routine result of «Дублировать»), **so that** the send log reliably shows the sends of the entity I actually picked — preserving per-campaign accountability down to every individual message.
