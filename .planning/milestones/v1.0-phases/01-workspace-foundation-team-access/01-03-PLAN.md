</objective>

| API → Platform SendGrid | System email dispatch with the platform key; must never use a tenant key |
| Browser → API (reset/verify) | Reset + verification tokens cross here |

## STRIDE Threat Register (ASVS L1, block_on: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Information Disclosure | platform-mail vs tenant key confusion | high | mitigate | Structurally separate platform-mail module reading only PLATFORM_SENDGRID_API_KEY; no import of the tenant KMS module (prohibition, grep-verified) |
| T-01-10 | Spoofing | Reset / verification tokens | medium | mitigate | better-auth cryptographically-random tokens with expiry; @fastify/rate-limit on reset-request; tokens single-use |
| T-01-11 | Information Disclosure | Reset-request account enumeration | low | accept | Reset-request returns a generic success regardless of whether the email exists; acceptable at L1 |
| T-01-12 | Elevation of Privilege | Change-password without current password | medium | mitigate | better-auth changePassword requires the current password; session rotation on password change |
</threat_model>
