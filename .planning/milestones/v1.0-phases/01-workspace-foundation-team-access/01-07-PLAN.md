<objective>
Close the single Phase 01 UAT blocker (Test 2, registration ECONNREFUSED) caused by cold-start env drift: plans 01-03 and 01-05 added required env vars to `apps/api/src/env.ts` (PLATFORM_SENDGRID_API_KEY, PLATFORM_MAIL_FROM per D-07; plus KMS_PROVIDER / KMS_LOCAL_KEK for envelope encryption), but `.env` and `.env.example` were never updated. `envSchema.parse(process.env)` throws a raw ZodError at import (env.ts:44), so the Fastify API exits before `listen()`. Purpose: Unblock the Phase 01 UAT re-run — registration, workspace creation, and SendGrid key connect all become reachable again on a clean cold start, and a future missing-env drift fails loudly instead of masquerading as healthy.
Output: Completed `.env` / `.env.example`, a readable boot error in `env.ts`, and a loud pre-dev env checker wired into `npm run dev`.
</objective>

Join the lines with newlines and `throw new Error(...)` with a header: a first line stating the API cannot start due to invalid environment configuration, a second line `Fix these variables (see .env.example):`, then the joined lines.

  - Keep `export type Env = z.infer<typeof envSchema>;` unchanged.
