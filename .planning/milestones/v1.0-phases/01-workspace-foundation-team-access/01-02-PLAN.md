From 01-01 (consume directly — do not re-derive):
- API base: /api (Vite dev proxy to the Fastify API; cookies must be sent with credentials: 'include')
- Auth routes: /api/auth/* (better-auth) — use better-auth's React client `createAuthClient` + its `organization` client plugin for sign-up/sign-in/session
- POST /api/workspaces  → body { name: string } → 200 { id, name, slug }
- GET  /api/workspaces/:slug → 200 { id, name, slug, role } for a member; 403/404 otherwise
- Session cookie is HttpOnly (set by 01-01); the client never reads it directly
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (React SPA) → Fastify API | Session cookie + form input cross here; the SPA holds no auth logic beyond the opaque cookie |
| Vite dev proxy → API | Dev-only same-origin proxy so the HttpOnly cookie is sent |

## STRIDE Threat Register (ASVS L1, block_on: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Spoofing | Session storage in the browser | medium | mitigate | Session lives only in the HttpOnly cookie; no token in localStorage/JS storage (prohibition, grep-verified) |
| T-01-06 | Tampering | CSRF on cookie-based auth mutations | medium | mitigate | better-auth trustedOrigins (set in 01-01) + SameSite cookie; the SPA calls same-origin /api via the dev proxy |
| T-01-07 | Information Disclosure | Auth error messages | low | accept | Generic «Неверный email или пароль» copy avoids account enumeration on login; acceptable at L1 for a dashboard SPA |
| T-01-08 | Elevation of Privilege | Client-side role gating | low | mitigate | Member-forbidden actions are hidden in UI but the server (01-01 role-guard) is the real enforcement layer; UI gating is convenience only |
</threat_model>
