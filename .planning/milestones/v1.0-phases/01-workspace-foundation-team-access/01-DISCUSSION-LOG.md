## Аутентификация

| Option | Description | Selected |
|--------|-------------|----------|
| Email/пароль | Классика: регистрация с паролем, сессии | ✓ |
| Email/пароль + Google OAuth | Меньше трения, но доп. интеграция в v1 | |
| Magic link | Без паролей, но зависит от системных писем с первого дня | |

**User's choice:** Email/пароль

| Option | Description | Selected |
|--------|-------------|----------|
| Да, обязательная верификация | Без подтверждения нельзя пользоваться | |
| Мягкая | Работать можно сразу; подтверждение для критичных действий | ✓ |
| Без верификации в v1 | Риск мусорных аккаунтов | |

**User's choice:** Мягкая верификация (обязательна для подключения SendGrid-ключа)

Также выбрано: сброс пароля в этой фазе; cookie-сессии (HttpOnly) ~30 дней sliding; готовая auth-библиотека (кандидат better-auth); 2FA — v2.

## Системные письма

| Option | Description | Selected |
|--------|-------------|----------|
| Свой SendGrid-аккаунт | Платформенный аккаунт только для системных писем | ✓ |
| AWS SES / другой провайдер | Дешевле, но второй вендор | |
| Copy-link без писем в v1 | Минимум работы, ломает верификацию и self-serve сброс | |

**User's choice:** Отдельный платформенный SendGrid-аккаунт

Также выбрано: инвайт = письмо + copy-link fallback; TTL 7 дней + отзыв/повтор; регистрация внутри инвайта; шаблоны системных писем в коде; from = noreply@домен платформы.
