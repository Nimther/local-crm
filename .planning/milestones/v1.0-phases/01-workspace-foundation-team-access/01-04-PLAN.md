## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API (invite/member/delete) | Role-sensitive mutations cross here; enforced server-side |
| Invite link → API | Untrusted invitation token crosses here at accept time |

## STRIDE Threat Register (ASVS L1, block_on: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Spoofing | Invite token brute force / enumeration | high | mitigate | better-auth cryptographically-random invitation tokens (not sequential); @fastify/rate-limit on accept/register-from-invite; 7-day expiry bounds exposure (D-11) |
| T-01-14 | Elevation of Privilege | Member/Admin exceeding role scope | high | mitigate | Server-side requirePermission on every mutation; explicit owner-only check for Admin-assignment/ownership-transfer (D-18); UI hiding is convenience only; proven by role-guard.test.ts |
| T-01-15 | Tampering | Accept invite binds to wrong workspace / role | medium | mitigate | Accept consumes the invitation row itself (workspace + role come from the server-stored invite, not client input); register-from-invite fixes the email to the invite |
| T-01-16 | Tampering | Accidental / unauthorized workspace deletion | medium | mitigate | Owner-only; server re-validates the typed workspace name equals the real name; soft delete (deleted_at) enables recovery, not immediate physical purge (D-20) |
</threat_model>
