## Phase Goal (gap-closure slice)

**As a** marketer, **I want to** set a custom quiet-hours window on a flow and have the platform actually withhold sends inside that window, **so that** my contacts are never emailed during the quiet period I explicitly configured.

This slice closes CR-02 (roadmap success criterion 3, FAILED in 06-VERIFICATION.md). Engine + schema + regression test only — the API/UI already send and persist 'custom' correctly.

<objective>
Unify the quiet_hours_mode vocabulary and make custom per-flow quiet hours actually gate sends.

Root cause (independently code-confirmed in 06-VERIFICATION.md): three incompatible vocabularies exist. The API/UI shared-schema (`packages/shared-schemas/src/flow.ts`) defines and QuietHoursCard.tsx sends `"workspace_default" | "custom" | "disabled"`; `flow.repository.ts` persists them verbatim; but the worker (`flow-run-advance.worker.ts` FlowRunAdvanceRow, `handlers/send-node.ts` FlowQuietHoursConfig + resolveQuietHoursWindow) uses `"inherit" | "override" | "disabled"` and only branches on `'override'`. A flow saved with `'custom'` never matches `'override'` and falls into the workspace-default branch, so its explicit window is silently ignored. `packages/db/src/schema/flows.ts` also carries the wrong DB default `"inherit"`.

Chosen canonical vocabulary: `"workspace_default" | "custom" | "disabled"` (the API/UI/shared-schema vocabulary — it is what is actually persisted). The worker is updated to this vocabulary; the DB default is corrected; stray legacy rows are migrated. Per 06-VERIFICATION.md's suggested fix, the worker branches on `'custom'` instead of `'override'`, and `'workspace_default'` (plus any legacy value) resolves to the workspace-default window.

Purpose: honor "no email is sent inside the quiet window, and it is deferred until the window ends" (FLOW-05).
Output: one canonical enum reused across layers, a corrected DB default + data migration, and a worker test that seeds the value the real API writes ('custom') and asserts deferral.

Note: this plan is wave 2 because it edits `send-node.ts`, `flow-run-advance.worker.ts`, and `flow-run-advance.test.ts` — the same files 06-12 touches. By the time this runs, 06-12 has already converted the delay/quiet-hours nudge assertions in flow-run-advance.test.ts from a fixed-jobId getJob to a getDelayed lookup; this plan only changes the seeded quiet_hours_mode value.
</objective>
