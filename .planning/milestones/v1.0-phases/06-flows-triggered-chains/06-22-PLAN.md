<objective>
Close the server-side half of UAT Test 10's gap (06-UAT.md 2026-07-13, FLOW-05; debug session .planning/debug/timezone-combobox-missing.md). The UI-SPEC promised a constrained IANA timezone combobox on the CSV column-mapping surface, but CsvImportWizard never rendered one — the surface only offered `timezone` as a mapping target. Per the debug session, a column-mapping UI maps columns to fields, so the semantically-correct realization of the promised combobox is a "default timezone for rows without one" control: a constrained IANA timezone the marketer picks once, applied server-side to any imported row that does not resolve a timezone from a mapped column.

This plan builds the server-side foundation that control needs so it is a real feature, not a decorative no-op: a persisted `csv_imports.default_timezone`, an optional `defaultTimezone` on the dry-run contract, and a single application+validation point inside the shared `applyCsvRowMapping` that BOTH the dry-run preview (apps/api) and the apply worker (apps/worker) already call — keeping preview and apply in lockstep exactly like the existing per-row timezone/subscription-status validation.

Direction chosen (of the two the debug session offered): wire the constrained timezone UI into the CSV mapping step, NOT realign the contract away to server-only per-row validation. Rationale: the UI-SPEC/FLOW-05 promise is a constrained combobox on that surface; realigning would delete a source-artifact promise (scope reduction), whereas the default-timezone control honors the promise literally AND delivers real value tied to FLOW-05 — imported contacts without a timezone get a deterministic zone for quiet-hours/wait-until resolution instead of only the workspace-default fallback. The frontend combobox itself ships in 06-23 (wave 2), which depends on the `defaultTimezone` contract field added here.

Purpose: give the CSV import a real, validated, persisted default-timezone capability so the (06-23) mapping-step combobox drives actual behavior.
Output: migration + drizzle column, an optional `defaultTimezone` on the dry-run schema, a default-aware validated `applyCsvRowMapping`, dry-run/apply threading, and pure-function mapper regression tests.
</objective>
