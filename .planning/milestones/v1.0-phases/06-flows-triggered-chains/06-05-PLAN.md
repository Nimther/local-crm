<objective>
Build the flow execution engine core: a durable state-machine step executor (flow-run-advance) plus a reconciliation scan backstop, handling the two node types needed for the thinnest end-to-end run — send and exit — with exit-condition evaluation at step boundaries (FLOW-03). Delays/wait-until (06-07) and branches (06-08) add handler modules later without reworking this dispatcher.

Purpose: This is the engine that actually moves a contact through a published flow and fires the send. Combined with the trigger evaluator (06-06), it completes the first user-observable E2E slice: event → run → email. FLOW-07 is enforced here by always resolving against the run's pinned version.
Output: flow-run-advance + reconciliation workers, send/exit handlers, exit-condition evaluator, registered in the worker runtime, with an integration test.
</objective>

> MVP user story (phase): **As a** marketer, **I want to** have contacts move through my published chain and receive its emails, **so that** automation runs without me. This slice is the running engine (send + exit + durable timers).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BullMQ nudge → advance | At-least-once wake nudges; a stale/duplicate nudge must not double-advance or double-send |
| cross-tenant discovery scan → per-tenant write | admin_scan SELECT-only; every write re-enters withTenant |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05-01 | Tampering | duplicate advance/send from a redelivered nudge | high | mitigate | re-read run FOR UPDATE SKIP LOCKED + stale-nudge no-op + deterministic advance/send jobId; state advance + step record in one tx |
| T-06-05-02 | Information Disclosure | admin-scan grants cross-tenant writes | high | mitigate | flow_runs_due_scan is SELECT-only; transition re-scopes via withTenant before any write (0027 policy) |
| T-06-05-03 | Repudiation | run advances against the wrong (mutated) version | high | mitigate | always resolve via the run's pinned flow_version_id, never live_version_id (FLOW-07) |
| T-06-05-04 | Denial of Service | lost BullMQ delayed job strands a waiting run forever | medium | mitigate | 60s reconciliation scan re-discovers any due run (Postgres is the timer source of truth) |
</threat_model>
