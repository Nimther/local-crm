<objective>
Close warning WR-01 (06-VERIFICATION.md / 06-REVIEW.md 2026-07-10), the verifier's highest-priority carried-forward warning: `deleteSegment`'s 23503 catch block calls `findReferencingFlowName(client, ...)` on a transaction that the failed DELETE already ABORTED. Postgres rejects every further statement with `25P02 current transaction is aborted`, so the intended `SegmentConflictError` (409) is never thrown — the raw 25P02 propagates and the route returns a 500. This is a regression introduced by THIS phase's own D-24 flow re-check addition, and it hits the canceled-campaign FK case the Rule-1 fix exists for. Direct user-facing impact: a marketer trying to delete a segment referenced by a canceled campaign gets an opaque 500 instead of a clear 409 conflict.

Repair the complete observable behavior as one vertical slice: first a failing regression test proving `deleteSegment` throws a raw postgres error (not a SegmentConflictError) when the DELETE trips a canceled-campaign FK, then the fix — wrap the DELETE in a `SAVEPOINT` and `ROLLBACK TO SAVEPOINT` in the catch so the flow re-check runs on a live transaction.

Purpose: Restore the actionable 409 conflict when deleting a segment referenced by a canceled campaign (D-24 / D-14 delete-when-referenced contract).
Output: a savepoint-wrapped deleteSegment and a regression test that fails under the current aborted-transaction code.
</objective>
