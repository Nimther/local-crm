<objective>
Close warning WR-05 (06-VERIFICATION.md / 06-REVIEW.md 2026-07-10), the verifier's second-highest-priority carried-forward warning: the canvas autosave `saveState` is derived solely from `mutation.isPending`, so the instant a PATCH FAILS the toolbar flips back to «Сохранено» — asserting the opposite of reality. The `onError` handler clears `lastSavedRef`, but the retry only fires when the debounced serialization next CHANGES; if the user makes no further edit (finishes editing, sees «Сохранено», closes the tab), the failed save is never retried and the canvas changes are lost while the UI claimed they were saved. Direct user-facing impact: silent draft loss.

Repair the complete observable behavior as one vertical slice, working within the web app's node-only test lane (no jsdom/@testing-library install — mirror `segmentSaveGate.test.ts`'s pure-function extraction precedent): first a failing pure-function regression test proving the derived state reads «saved» after a failed save, then the fix — extract a pure `deriveAutosaveState`, add an `error` state, render it honestly in the toolbar, and schedule an automatic retry so a failed save is not left un-retried.

Purpose: The autosave indicator must never claim «Сохранено» when the last save failed, and a transient failure must self-heal without a further edit.
Output: a pure, tested `deriveAutosaveState`, an honest toolbar error/retry state, an automatic retry, and a regression test that fails under the current isPending-only derivation.
</objective>
