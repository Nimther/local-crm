<objective>
Make flow runs visible and controllable without building Phase-7 analytics: the "N in flow (M on old versions)" counter (D-21, the FLOW-07 immutability made visible), the eject intervention (single + bulk), and the D-22 delete guard. This is the minimum run-management surface the phase requires; per-step analytics is Phase 7 (ANLT-02).

Purpose: The user can see how many contacts are mid-flight (and how many are on superseded versions) and remove contacts, honoring the no-migration guarantee.
Output: flow-run.repository + run/eject/delete routes wired into the existing flows module.
</objective>

> MVP user story (phase): **As a** marketer, **I want to** see how many contacts are in my chain (and how many are on old versions) and remove a contact if needed, **so that** I trust and control what's running.
