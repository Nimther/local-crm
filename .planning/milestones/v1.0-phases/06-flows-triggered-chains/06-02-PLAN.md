<objective>
Create the shared, database-free contracts every flow slice depends on: the flow-definition Zod schema (nodes/edges), the pure publish-time validator (D-17 hard errors), the route DTOs, and the discriminated-union job schema that lets the send pipeline carry a flow-step send. Interface-first: these contracts land in Wave 1 so downstream API (06-04), engine (06-05), and UI (06-10) build against them without a scavenger hunt.

Purpose: One node/edge model + one validator shared by canvas (instant feedback) and server (authority) prevents the Pitfall-3 client-only-validation gap. The discriminated-union job schema is the type seam for kind:'flow' sends.
Output: `@mega-crm/flows-core` package + shared-schemas flow additions, unit-tested.
</objective>

> MVP user story (phase): **As a** marketer, **I want to** visually build, publish, and run automated triggered chains, **so that** the right contacts receive the right emails automatically. This plan is the shared contract layer; it uses TDD because the publish validator has crisp input→output cases.

<feature>
  <name>Flow definition schema + pure publish validator</name>
  <files>packages/flows-core/src/flow-definition-schema.ts, packages/flows-core/src/flow-validate.ts, packages/flows-core/src/__tests__/flow-validate.test.ts</files>
  <behavior>
    - A well-formed flow (trigger → send(with templateId+sender) → exit) → validateFlowDefinition returns [] (no hard errors).
    - A flow with no trigger node → returns an error with code "no_trigger".
    - A flow whose send node has no templateId or no sender → returns an error with code "empty_send" naming the node id.
    - A flow with a branch whose "no" path does not terminate in an exit node → returns an error with code "branch_missing_exit" naming the offending path.
    - A flow with a dead/orphan branch that STILL satisfies the three hard requirements → returns [] (no v2 linting in v1, D-17).
    - flow-definition-schema parses valid node/edge JSON and rejects an unknown node type.
  </behavior>
  <implementation>Implement validateFlowDefinition as a pure function over the parsed FlowDefinition (walk nodes/edges; no DB). Return an array of {code, nodeId?, message} where code ∈ {"no_trigger","empty_send","branch_missing_exit"}. Messages are keys/identifiers only — the UI (06-11) maps them to Russian copy.</implementation>
</feature>
