<objective>
Close warning WR-04 (06-REVIEW.md / 06-VERIFICATION.md 2026-07-10), the highest-priority safety warning surfaced by the gap-closure code review: `publishFlow` unconditionally sets `status = 'live'`, and 06-14 now shows the "Опубликовать изменения" button for PAUSED flows — so a marketer who paused a misbehaving flow, edited the draft, and clicked "publish changes" silently resumes live enrollment and frozen in-flight runs, with no warning. This contradicts locked decisions D-18 (pause = full freeze: no new entries, no step execution) and D-19 (resume is the explicit path) and undermines roadmap success criterion 4 / FLOW-06's draft → live → paused state machine. Risk: unintended email sends.

Repair the complete observable behavior as one vertical slice, using the SAFE-by-default fix from WR-04 (preserve `paused` on publish — publish the version, keep enrollment paused, leave "Возобновить" as the sole resume path): first a failing API-level regression test proving publish-on-paused keeps the flow paused, then the repository fix plus honest dialog copy for the paused case.

Purpose: Publishing a fix to a paused flow must never silently resume sending (D-18/D-19, FLOW-06 safety).
Output: status-preserving `publishFlow`, paused-aware publish dialog copy, and a regression test that fails under the current code.
</objective>
