## Phase Goal (gap-closure slice)

**As a** marketer, **I want to** edit a live flow's trigger on the canvas as a draft that only takes effect when I publish, **so that** an unfinished edit never silently re-targets who is being enrolled into my live flow.

This slice closes CR-03 (roadmap success criterion 4, FAILED in 06-VERIFICATION.md) and its compounding warning WR-03 (no UI path to publish an accumulated draft on a live/paused flow).

<objective>
Isolate draft trigger edits from live enrollment until publish, and give the UI a way to publish those changes.

Root cause (independently code-confirmed in 06-VERIFICATION.md): `flow.repository.ts` `updateFlowDraft` computes and syncs `trigger_type`/`trigger_event_name`/`trigger_segment_id` from the draft definition onto the `flows` row on EVERY definition PATCH, regardless of flow status. The canvas autosaves every change (useAutosaveDraft.ts), and `flow-trigger-evaluator.worker.ts` + `flow-segment-sweep.worker.ts` select live-enrollment candidates against those SAME columns — so an unpublished draft edit to a live flow's trigger immediately re-targets live enrollment, while `flows.live_version_id` (and every in-flight run) still points at the old published version. This is the literal negation of "editing a live flow only takes effect on publish." Compounded by WR-03: `FlowDetailPage.tsx`'s lifecycleButton renders a publish action only for `status === 'draft'`, so there is no UI path to publish an accumulated draft on a live/paused flow at all.

Fix (per 06-VERIFICATION.md missing list): sync trigger columns from the draft ONLY while `status = 'draft'`; for live/paused flows keep them pinned to the published definition and re-derive them inside `publishFlow` from the version being published. Add a UI publish-changes action when `flow.draftVersionId` is set on a live/paused flow.

Purpose: honor "editing a live flow happens in a draft that only takes effect on publish" (FLOW-06).
Output: status-gated trigger sync, publish-time trigger re-derivation, a live/paused publish-changes UI action, and an API regression test proving the columns stay pinned until publish.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| autosaved draft PATCH -> flows.trigger_* columns | An unpublished draft must not be able to change live-enrollment targeting; the write is gated on flow status |
| web client -> POST /flows/:id/publish | Publish is Owner/Admin only (D-23) and server-authoritative (re-validates the definition); the UI gate is not the only control |

| T-06-14-01 | Tampering | updateFlowDraft trigger-column sync | high | mitigate | Trigger columns sync from the draft only while status='draft'; for live/paused they stay pinned to the published definition, so an unpublished (autosaved) edit cannot re-target live enrollment. publishFlow re-derives them from the published version as the single change point. Covered by an API regression test. |
