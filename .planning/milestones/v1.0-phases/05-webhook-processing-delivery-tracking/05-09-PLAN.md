<objective>
Carry the provisioning-failure reason from the SendGrid client response, through the API route contracts, all the way to the rendered UI state — in one vertical slice, per the gap-closure directive. This closes both diagnosed UAT failures' user-facing halves: connect/recheck now render the existing `webhookWarning` (which the UI ignored), a scope-lacking key is caught deterministically at connect time, and Reconnect stops firing a success toast while the badge flips to error — it now shows the real reason and the health card explains it. It also persists the created webhook id on signed-verification failure (using the optional `webhookId` added in 05-08) so a reconnect self-heals via PATCH.

Purpose: Make the failure self-explanatory to the marketer and stop the lying success toast (UAT Test 1 + Test 3 presentation defects).
Output: Connect-time webhook-scope detection, a shared warning-copy module, reconnect error propagation, a `provisionError` field on the health contract, and the rendered UI (inline warning + reconnect error toast + health-card reason) backed by a pure, unit-tested decision helper.
</objective>

## Phase Goal

**As a** marketer connecting my SendGrid account, **I want to** see clearly whether delivery tracking was set up — and a specific reason when it was not — **so that** I can fix my key's permissions or my environment instead of silently receiving no delivery statistics.

(Derived for this gap-closure round from the ROADMAP Phase 5 goal plus UAT Tests 1 and 3. This slice is the rendered-UI end of the failure-visibility path whose backend substrate lands in 05-08.)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant BYO key → scope check (sendgrid-client) | The decrypted key is used to read /v3/scopes; the trust decision (webhook scope present) is derived here |
| API → browser | provisionError / webhookWarning copy is returned to the client and rendered |
| browser → API (reconnect) | Owner/Admin-gated mutation that decrypts and uses the live key |
