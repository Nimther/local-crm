## Правила suppression

### Bounce → suppressed

| Option | Description | Selected |
|--------|-------------|----------|
| Только hard bounce (рекомендую) | Hard сразу; soft — только факт в леджере | |
| Hard сразу + soft после N подряд | Hard сразу; soft — после N подряд неудач | ✓ |
| Любой bounce → suppressed | Максимально агрессивно | |

**Notes:** Пользователь выбрал вариант с эскалацией soft bounce (не рекомендованный минимум) — защита репутации отправителя важнее простоты MVP.

### Порог soft bounce

| Option | Description | Selected |
|--------|-------------|----------|
| N=3, платформенная константа (рекомендую) | Без настройки; успешная доставка сбрасывает счётчик | ✓ |
| N=5, платформенная константа | Мягче к базе | |
| Настройка воркспейса | Дефолт 3, редактируемо | |

### Dropped → suppression?

| Option | Description | Selected |
|--------|-------------|----------|
| Да, по причине (рекомендую) | Bounced/Spam/Invalid Address → suppressed; Unsubscribed Address → unsubscribed | ✓ |
| Нет, только факт в леджере | Статус не меняется | |

### Запись в workspace_suppressions

| Option | Description | Selected |
|--------|-------------|----------|
| Статус + список сразу (рекомендую) | suppressed-события пишут и статус, и email в список с причиной; unsubscribe — только статус | ✓ |
| Только статус контакта | Список пополняется лишь при удалении (текущая механика D-08) | |

## Claude's Discretion

- Формат per-tenant webhook URL и хранение verification key
- Схема очереди обработки и батчинг вставки событий
- SendGrid scopes для автонастройки; поведение при нехватке прав
- Реализация счётчика soft-bounce-подряд (гонки при параллельной обработке)
- Механика счётчиков сводки кампании (инкрементально vs агрегат)
- Реакция на смену/отключение SendGrid-ключа
- Обновление «последнее событие получено» без лишней нагрузки
- RLS новых таблиц, tenant context в воркере, русскоязычные UI-тексты
