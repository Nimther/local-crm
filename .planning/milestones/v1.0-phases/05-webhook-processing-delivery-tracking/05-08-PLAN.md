<objective>
Make SendGrid webhook provisioning failures diagnosable and non-destructive at the source. Today every non-ok SendGrid response collapses to a typed error with no logging (undiagnosable), a created webhook id is thrown away if signed-verification then fails, and the DB persists only `provision_status='error'` with no reason. This plan adds redacted status+body logging, preserves a created webhook id on signed-verification failure, and adds a persisted `provision_error` column + repository threading so a later slice can surface the reason to the marketer.

Purpose: Close the "silent failure" root cause shared by UAT Test 1 and Test 3 — an operator must be able to see WHY provisioning failed, and no created webhook may be silently orphaned.
Output: Observability logging in the provisioning module, a backward-compatible provisioning-result contract change, a new `provision_error` column + migration, and repository support for persisting/reading the typed reason.
</objective>

## Phase Goal

**As a** marketer connecting my SendGrid account, **I want to** see clearly whether delivery tracking was set up — and a specific reason when it was not — **so that** I can fix my key's permissions or my environment instead of silently receiving no delivery statistics.

(Derived for this gap-closure round from the ROADMAP Phase 5 goal plus the two diagnosed UAT failures. This plan delivers the substrate — visible failures and a persisted reason — that the wave-2 slice renders to the user.)

## Artifacts this phase produces

- `redactSecret(text: string, apiKey: string): string` — new helper in `sendgrid-webhook-provision.ts` that removes the plaintext api key from an arbitrary string (mirrors the existing `redactApiKey` approach for strings, not just `Error`).
- `logNonOkProvisionResponse(context: string, res: Response, apiKey: string): Promise<void>` — new helper in `sendgrid-webhook-provision.ts` that reads the response body text, redacts the api key, and `console.warn`s `context`, `res.status`, and the redacted body.
- `ProvisionEventWebhookResult` — error variant widened to `{ error: ProvisionEventWebhookError; webhookId?: string }` (backward compatible; `webhookId` optional).
- `workspace_webhook_endpoints.provision_error` — new nullable `text` column (Drizzle field `provisionError`).
- `packages/db/migrations/0025_webhook_provision_error.sql` — migration adding the column.
- `UpsertWebhookEndpointInput.provisionError?: string | null` — new optional repository input field.
- `WebhookEndpointRow.provisionError: string | null` — new repository read field.
