<objective>
Turn the dedup-only webhook worker (05-01) into the full delivery-status + suppression engine, wiring in the pure decision logic from 05-02. For each genuinely-new (RETURNING-gated) event the worker: writes the matching fact column on `sends` idempotently (D-06), increments the right campaign counter exactly once per unique recipient (D-09), applies the suppression state machine (D-10/D-11/D-12/D-13) as a dual write to `contacts.subscription_status` + `workspace_suppressions`, maintains the soft-bounce streak (D-10 N=3), short-circuits test events (D-15), tolerates orphaned sends (D-15), and debounces the webhook health timestamp (D-03) — all inside one tenant-scoped transaction.

Because every side effect targets columns that do not exist yet, this plan owns the schema ALTERs and a BLOCKING migration push.

Phase Goal (user story): **As a** marketer, **I want to** see accurate, deduplicated delivery outcomes for my sent emails and have bounces/spam-complaints/unsubscribes automatically suppress contacts, **so that** my stats are trustworthy and I stop mailing dead or opted-out addresses.

Purpose: Deliver WBHK-04 + SUBS-02 end-to-end with exactly-once, order-insensitive semantics (PITFALLS #3), closing the send loop.
Output: 3 migrations (pushed), the completed worker, and its integration test suite.
</objective>
