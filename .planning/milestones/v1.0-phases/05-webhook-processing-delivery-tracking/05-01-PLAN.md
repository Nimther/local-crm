<objective>
Build the delivery-event receiver walking skeleton end-to-end: a signed SendGrid Event Webhook batch arrives on a per-tenant, unguessable URL, is ECDSA-verified against the RAW request bytes before any parsing, acknowledged fast (200), and processed asynchronously by a new worker that dedup-inserts each event into a new month-partitioned `send_events` table keyed on `(workspace_id, sg_event_id)`.

This plan delivers the complete "signed POST → verified → deduped rows in Postgres" slice. It deliberately stops BEFORE side effects (fact columns, campaign counters, suppression) — those are 05-03. Storage + dedup is the foundation every later slice builds on.

Phase Goal (user story, faithful reframing of ROADMAP Phase 5 goal — the ROADMAP `**Goal:**` line was a plain statement, not `As a…/I want to…/so that…` form):
**As a** marketer, **I want to** see accurate, deduplicated delivery outcomes for my sent emails and have bounces/spam-complaints/unsubscribes automatically suppress contacts, **so that** my stats are trustworthy and I stop mailing dead or opted-out addresses.

Purpose: Close PITFALLS #2 (raw-body verification) and #3 (per-event dedup by sg_event_id) with the DB unique constraint as the exactly-once boundary (WBHK-01, WBHK-03, D-14, D-16).
Output: New tables + migrations (pushed), the public webhook route, the signature-verify wrapper, the queue contract, and the dedup-only worker.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SendGrid → public webhook route | Untrusted HTTP crosses here; the ONLY trust anchors are the URL pathToken (pre-verification tenant resolution) and the ECDSA signature (authenticity) |
| API route → BullMQ queue | Only verified batches are enqueued |
| Worker job → Postgres | workspaceId re-derived from job.data; RLS + withTenant enforce isolation |
