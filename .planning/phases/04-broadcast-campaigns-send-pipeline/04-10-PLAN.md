## Phase Goal

**As a** marketer, **I want to** trust that once an email is recorded as sent it stays sent, **so that** a queue redelivery never erases delivery evidence or lets a contact be re-sent past the frequency cap.

<objective>
Close CR-07 (verification truth #4, SEND-04/SEND-06). `recordExcluded` (`send-ledger.ts:77-84`) uses an unconditional `ON CONFLICT (workspace_id, campaign_id, contact_id) DO UPDATE SET status='excluded'`. On a kickoff redelivery before `fan_out_complete` is set, the exclusion re-walk can DEMOTE a row that is already `sent` (or in-flight `dispatching`) to `excluded`. Because `pre-send-gate.ts` counts this same campaign's own `status='sent'` rows for the rolling frequency-cap window, demoting a `sent` row both erases delivery history and can let the contact be re-sent past the cap. This plan adds a status guard so `recordExcluded` only ever writes over a non-terminal, non-in-flight row.

Purpose: protect the send ledger's integrity (the single source of truth for progress, frequency cap, and later per-message delivery tracking) under at-least-once kickoff redelivery.
Output: guarded `recordExcluded` + a regression test proving a `sent` row survives a subsequent exclusion attempt.
</objective>
