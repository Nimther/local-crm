<objective>
Build the shared delivery-core library and the public compliance surface: a new `@mega-crm/delivery-core` package holding the send-pipeline logic that BOTH apps/api and apps/worker must share without drift — HMAC unsubscribe token sign/verify, the `mail/send` request builder + List-Unsubscribe header, the per-contact pre-send gate (suppression / subscription / frequency-cap), the idempotent send-ledger writer, and workspace-send-settings access — plus the public RFC 8058 unsubscribe endpoint in apps/api.

Purpose: The dispatch worker (04-04, a separate process) signs the unsubscribe token, runs the pre-send gate, and records the ledger; the campaign API (04-05) computes the D-04 exclusion breakdown from the same gate rules; the public endpoint verifies the token. Putting these in one shared package is the concrete defense against RESEARCH's central warning — a second, subtly-different implementation of a send rule. This delivers the suppression-aware and unsubscribe-compliant guarantees of the phase goal.
Output: `@mega-crm/delivery-core`, public unsubscribe route.
</objective>

## Phase Goal (MVP user story)

**As a** marketer, **I want to** send a broadcast to a segment through a throttled, idempotent, suppression-aware queue, **so that** my emails reliably reach inboxes via SendGrid Dynamic Templates with per-message unsubscribe and frequency-cap compliance.

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03-01 | Tampering / Elevation of Privilege | unsubscribe token forgery to flip another contact | high | mitigate | HMAC-SHA256 over sendId+contactId+workspaceId+exp with a platform secret; timing-safe compare; verify server-side before any status write; reject → generic response |
| T-04-03-02 | Information Disclosure | unsubscribe endpoint as cross-tenant enumeration oracle | high | mitigate | Identical response for invalid-signature and unknown-contact; no tenant-identifying content on the page; no differing status codes |
| T-04-03-03 | Tampering | GET prefetch silently unsubscribing | medium | mitigate | GET never mutates; only POST (one-click header or explicit form submit) flips status (RFC 8058) |
| T-04-03-04 | Information Disclosure | tenant SendGrid key leaked in mail-send error logs | high | mitigate | sendTenantMailV3 redacts the Authorization header on any thrown/logged error |
| T-04-03-05 | Denial of Service | frequency-cap count query per send at volume | medium | mitigate | Query uses the (workspace_id, contact_id, sent_at) index from 04-01; cap check batchable into the breakdown query |
