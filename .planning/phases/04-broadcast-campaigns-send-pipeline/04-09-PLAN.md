## Phase Goal

**As a** marketer, **I want to** send a test email from a campaign I configured by picking a verified sender in the builder UI, **so that** I can preview the real email before launching a broadcast.

<objective>
Close CR-02 (verification truth #1, CAMP-04/CAMP-02): the campaign builder only ever writes `fromSenderId` (a numeric SendGrid verified-sender id, stored as a string), but the dispatch worker (`send-dispatch.ts:155`) hard-requires `campaigns.from_email` for BOTH `kind='campaign'` and `kind='test'`. Nothing in the codebase resolves `fromSenderId` to an email, so every UI-created campaign is undispatchable. This plan adds a resolver that reads the tenant's verified senders from SendGrid (D-17), converts the selected `fromSenderId` to its verified email, and persists it to `campaigns.from_email` at launch, schedule, and test-send time — before any job is enqueued.

Purpose: without this, zero emails can be delivered through any UI-configured campaign; this unblocks every other gap plan.
Output: `resolveCampaignFromEmail` resolver + wiring into the launch/schedule/test-send routes + a real-contract integration test (campaign with `fromSenderId` and NO `fromEmail`).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| marketer (Owner/Admin) → campaigns API | Authenticated tenant user supplies a fromSenderId that the server must not trust as an email source |
| campaigns API → SendGrid v3 API | Tenant's decrypted BYO key crosses to SendGrid to read verified senders |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09-01 | Spoofing | resolveCampaignFromEmail | medium | mitigate | Only accept a fromSenderId that appears in SendGrid's own /v3/verified_senders list; an unmatched id fails closed (CampaignSenderError sender_not_found → 422), so a forged/stale id can never inject an arbitrary From address |
| T-04-09-02 | Information disclosure | sender-resolver.ts key handling | high | mitigate | Decrypted tenant key is used only for the verified_senders fetch and never logged; resolver reuses the existing decrypt path and adds no logging of the plaintext key |
| T-04-09-03 | Tampering | campaigns.from_email persistence | low | mitigate | Persist UPDATE is workspace-scoped (WHERE workspace_id) inside withTenantTransaction/RLS, so resolution cannot write another tenant's campaign |
| T-04-09-SC | Tampering | dependencies | low | accept | No new package installs; reuses existing @mega-crm/kms and sendgrid-client |
</threat_model>
