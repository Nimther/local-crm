<objective>
Close DB-07: make rollback and roll-forward a rehearsed procedure rather than a hope. Drizzle migrations are forward-only and this repository's snapshot history is incomplete, so "rollback" is genuinely two different operations depending on what the migration did — D-15 puts the rehearsal in CI on every PR precisely so it cannot rot, and the ROADMAP requires the snapshot backfill be an explicit task rather than an assumed side effect.

## Investigation this plan must do before deciding scope

Two facts decide how much snapshot backfill is actually needed, and both must be established by reading and running, not assumed:

1. **How many snapshots `drizzle-kit generate` actually consumes.** drizzle-kit diffs the TypeScript schema against snapshot history; if it reads only the newest snapshot, then "backfill all 52" and "the empty-diff gate passes" are different goals and the second one may already be nearly satisfied. Determine this from `node_modules/drizzle-kit` and from an actual run before generating 52 files nobody consumes.
2. **What `test:migrations` needs.** The existing suite applies the whole chain to an empty database; that path reads SQL files, not snapshots. If it passes today, snapshots are not what makes it pass.

The ROADMAP's requirement is that the backfill be an explicit task with a measurable completion criterion. Use the ROADMAP's own criterion as that measure — `drizzle-kit generate` produces an empty diff AND `test:migrations` is green — and backfill exactly as far as those require. If the investigation shows that a full 52-file backfill is unnecessary to satisfy both, record that finding with its evidence in the SUMMARY instead of generating files for their own sake. If it shows the full backfill IS required, do it. Either way the answer is evidence, and both the measured migration count and snapshot count must be recomputed at execution time rather than copied from this plan.
