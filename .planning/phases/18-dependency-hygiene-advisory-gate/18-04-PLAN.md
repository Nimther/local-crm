<objective>
Give the gate a heartbeat: run it daily on master and surface a failure to a human, through the
same script and the same reporting path the PR gate uses.

Purpose: DEP-02's second half and ROADMAP SC3 — an advisory published tomorrow against a dependency
already installed today must surface with no code change on the branch. Per D-12 this lives in its
own workflow rather than a `schedule:` trigger on ci.yml, so a daily tick does not spin the entire
Postgres/Redis/browser matrix, and "same reporting path" is satisfied by executing the identical
npm script. Per D-13 a failed run opens or updates one labelled GitHub issue naming the package and
advisory id; the rejected alternative was an operator-alert email, which would wire CI into the
application's own unobserved mail path. Per D-14 the cadence is daily, and that cadence is
deliberately load-bearing: an accept-list entry that lapses during a quiet period turns the cron red
inside a day, so D-05's expiry is enforced even with zero pull-request activity.

Output: `.github/workflows/advisory-scan.yml`, a drift test that pins its invariants, and
SPECIFICATION.md section 7.
</objective>
