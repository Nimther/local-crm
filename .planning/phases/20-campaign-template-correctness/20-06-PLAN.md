<objective>
Turn a refused send into a recoverable, honest interaction: the dialog stays open, the copy says what actually happened, the page refreshes to the truth, and nothing re-sends on its own. Then prove SC1 and SC3 by clicking through the real app.

Purpose: plans 20-02 and 20-03 make the server answer 409 with a typed code; today the client shows «Что-то пошло не так» for every failure, which teaches the marketer nothing and hides the one thing they need to know — that the campaign changed under them. This plan is also the phase's only interaction-level proof: the web unit lane has no DOM, so the click-through lives in the existing Playwright lane.

Output: a pure conflict classifier with its copy, wired into all three send mutations; an end-to-end spec covering blocked-while-unsaved and conflict-with-nothing-dispatched; and a human verification of the full marketer flow against a real SendGrid template.
</objective>

## Flagged assumptions

The fallback edge-coverage rows for TMPL-01 and TMPL-02 came back `unclassified`/`unresolved` (English-keyed classifier, Russian requirement text). This plan assumes the recoverable-conflict surface is exactly the two 409 codes (`version_conflict`, `illegal_transition`); a 4xx/5xx outside that set keeps today's generic copy deliberately. Full statements in `20-01-PLAN.md`.

## Resolved research questions

- **How the illegal-transition copy learns the real state (RESEARCH Pitfall #2 leaves it open):** the 409 body for `illegal_transition` does not carry the status, and reading `err.message` would be exactly the brittle coupling D-09 is moving away from. Instead the component stores the conflict KIND in state and renders the copy at render time from the live `campaign` prop, which the refetch has already refreshed — so the named state is always the fresh one, with no extra server field and no second request.
- **Why the refetch uses the campaigns key prefix:** `campaignsQueryKey(slug)` is `["workspace", slug, "campaigns"]`, and TanStack Query invalidation is prefix-matching, so it refreshes both the list and the campaign detail query the detail page and the embedded builder read. That existing helper is reused rather than adding a second key literal.
- **Why the interaction proof is Playwright, not a component test:** `apps/web`'s unit lane is `environment: "node"` with no jsdom and no Testing Library, so a click cannot be simulated there. `apps/web/e2e/flow-unsaved-changes.spec.ts` is the established precedent for proving exactly this class of behaviour (unsaved-state guards) with the fail-closed provisioned database in `run-e2e.ts`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API error response → browser | the typed `code` crosses here and selects the recovery path; the body is data, never instructions |
| marketer intent → a second send attempt | the boundary an auto-retry would silently cross |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-06-01 | Repudiation | an automatic retry sending mail the marketer never re-confirmed | high | mitigate | The error handler only sets state and invalidates queries; the mutation is not re-invoked and no `retry` option is added (TanStack's mutation default is no retry). Pinned by a request-count assertion in the end-to-end spec. |
| T-20-06-02 | Information Disclosure | error copy echoing server internals to the marketer | low | mitigate | Copy is composed from the typed code plus the campaign's own status label; `err.message` is never rendered. |
| T-20-06-03 | Tampering | treating client-side classification as the control | low | accept | The refusal already happened server-side under lock (plans 20-02/20-03); this layer is presentation and recovery only, and a tampered client gains nothing. |
| T-20-06-04 | Repudiation | unsaved edits replaced by a refetch with no notice | medium | mitigate | The conflict path emits an explicit notice that the campaign data was refreshed and local unsaved changes were replaced by the saved values (D-10), so a silent substitution cannot happen. |
| T-20-06-SC | Tampering | npm/pip/cargo installs | n/a | accept | No installs: `@playwright/test` and every other dependency used here is already pinned in `apps/web`. |
</threat_model>
