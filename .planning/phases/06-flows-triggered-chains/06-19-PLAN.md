<objective>
Close blocking gap "segment-triggered re-entry is dead for every_time/once_per_n_days" (06-VERIFICATION.md 2026-07-10, roadmap success criterion 3 / FLOW-04; fresh-review WR-04): `flow_segment_membership_snapshot` rows are only ever inserted, never deleted, and `checkSegmentEntryForContact` short-circuits on `hasSeenSnapshot` BEFORE `canEnterFlow` is reached. So once a contact is marked "seen" for a segment-triggered flow, a subsequent leave-then-rejoin of the trigger segment — an entirely routine occurrence — never re-enters the flow regardless of `reentry_mode`, while the UI presents all three re-entry modes as functional. `canEnterFlow`'s per-mode logic is itself correct but unreachable a second time.

Repair the complete observable behavior as one vertical slice using the verifier-prescribed option (a): make the periodic sweep delete a contact's snapshot row when that contact no longer matches the trigger segment, so "seen" means "currently in this membership episode" and a leave→rejoin re-enters subject to `canEnterFlow`'s existing, correct per-mode decision. First a failing leave→rejoin regression test (every_time must re-enter; once_ever must stay blocked), then the bounded stale-delete in `sweepOneFlow`.

Purpose: Restore the re-entry controls (every_time / once_per_n_days / once_ever) as functional for segment-triggered flows, matching the literal roadmap wording under ordinary usage.
Output: a bounded stale-snapshot delete in the sweep and a live-run regression test that fails under the current insert-only snapshot code.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Periodic segment sweep -> Postgres (per tenant) | The sweep decides, from stored contact/segment data, whether a contact should (re)enter a flow. A wrong "already seen forever" decision silently disables a marketer-configured re-entry mode; a wrong delete could cause unwanted re-enrollment. |
| Sweep snapshot state -> canEnterFlow | The snapshot gate must hand control back to canEnterFlow on a genuine leave->rejoin, but must NOT bypass canEnterFlow's once_ever / active-run / window denials. |
