## Why an age-out DELETE and not the journal's prune/purge split

`ingress_journal` splits retention in two (`pruneIngressJournal` deletes completed rows outright; `purgeExpiredIngressJournalPayloads` nulls an incomplete row's payload and leaves a tombstone) for one specific reason: an un-ingested journal row is the only remaining evidence that ingestion lost a batch, and plan 13-11's watchdog alerts on exactly those rows. Deleting them would end the alert by destroying the signal rather than fixing the problem.

None of that applies to a quarantined event:

- It is a terminal decision, not an incomplete one. The platform examined the event and refused it; there is no pending outcome for a tombstone to keep visible.
- It has no replay value — `occurred_at_candidate` is deliberately `text` precisely so the value can never be trusted to route a partition, so the row can never become a `send_events` row later.
- Nothing reads it cross-workspace. Migration 0055 deliberately gave this table no `mega_crm_scan` grant and no scan policy, so no watchdog, alert, or health surface depends on its rows continuing to exist.

So the disposal is a plain age-out `DELETE`, and the row goes with the payload. The verifier's `missing:` entry names this same shape as sufficient. The asymmetry with the sibling table is deliberate and must be stated in the code, or a future reader will read it as an oversight and "fix" it into a tombstone that nothing consumes.

**Reading of "bounded" in the verifier's wording:** bounded refers to the retention *horizon* (a finite, versioned number of days), not to a `LIMIT` on the delete statement. The statement shape mirrors `pruneIngressJournal` — the verifier's own named reference — which is itself a single unbounded-per-call `DELETE` inside the same tenant transaction. See `<threat_model>` T-13-16-03 for the accepted consideration this implies.

|----------|-------------|
| SendGrid → webhook ingress | Provider-controlled event bodies cross here. | stored quarantine PII → time | Retention is the control. The row's exposure window is the horizon and nothing else — there is no access-control story that makes an indefinitely-retained raw recipient address acceptable. |
