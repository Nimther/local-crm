<objective>
Close CMP-01. Today the public unsubscribe route updates the contact's status and consent history but never touches the originating send — even though the signed token already carries `sendId` — while the webhook path writes the send fact, the status, the history and the counters together. Two paths, two behaviors, one of them incomplete. Collapse both onto one shared helper inside one transaction, and prove atomicity with a failure-injection scenario on Phase 8's harness.

Purpose: "an unsubscribe is honored everywhere at once" is half of the phase goal. A route unsubscribe that leaves `sends.unsubscribed_at` null means the send log and the campaign's unsubscribe counter disagree with the contact's own consent record.
Output: `applyUnsubscribeWithSendFact` in `contacts-core`, all three call sites converted, a both-orderings convergence test, and a new `failure:unsubscribe-atomic` script.
</objective>

The function's contract, in this order:
1. Resolve the send row when `sendId` is present: select `id`, `campaign_id`, `contact_id` from `sends` scoped to `workspaceId`. A missing row is normal, not an error — a test send never writes a `sends` row at all, and a pre-04-19 token can name a send that no longer exists.

5. Call `recordSubscriptionStatusChange` only when the prior status was non-null and not already `unsubscribed`, preserving the existing caller-gated no-op rule exactly.
