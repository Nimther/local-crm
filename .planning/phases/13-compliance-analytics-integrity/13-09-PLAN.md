<objective>
Build CMP-09's measurement half (D-09 through D-12): compute each tenant's spam-complaint rate and hard-bounce rate over a rolling window from the delivery fact columns the platform already records, tier them against the Gmail/Yahoo bulk-sender lines, and persist the observation into a per-workspace-per-metric alert-state table. Plan 13-11 turns a recorded tier crossing into operator and tenant email.

Purpose: the audit found this gap and noted the data was already there — the alert is cheap. The expensive mistake would be copying the existing watchdogs' singleton alert-state shape, which can only track one workspace platform-wide.
Output: a pure tiering function with versioned thresholds, migration 0058 (the keyed reputation table plus the singleton ingestion-health table plan 13-11 also needs), and a scheduled reputation tick.
</objective>
