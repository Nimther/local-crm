<objective>
Fix the CMP-02 day-semantics defect and pin the contract: every `::date` cast in the reconciler currently truncates a `timestamptz` using the session's `TimeZone` GUC, not UTC, so the same reconciliation run can produce different daily numbers depending on which pooled connection served it. Make `sent_at` the documented authority for a send's day (D-13), force every cast to UTC, and record the contract where both write paths can see it.

Purpose: "a daily number means exactly one thing" is the phase goal; a session-dependent cast makes that literally false today.
Output: UTC-forced reconciliation queries, an explicit day-semantics contract in `workspace-daily-rollup.ts`, and a test that runs the same reconciliation under three different session timezones and asserts identical output.
</objective>
