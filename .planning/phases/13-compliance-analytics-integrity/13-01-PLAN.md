<objective>
Establish the durable webhook ingress record (CMP-08, D-05) end-to-end: a verified SendGrid batch is written to `ingress_journal` inside the request that verified it, the enqueued job carries the journal id, and the worker closes the loop by marking ingestion complete. Also lands the `send_event_quarantine` table DDL and its insert-only writer, which plan 13-04 wires into the worker's bounding path.

Purpose: post-receipt loss (Redis flush, worker crash, bad deploy) becomes replayable without any paid provider API. This is the phase's tracer — it proves the ingress → journal → queue → worker → completion-mark path before any of the other four tracks build on it.
Output: migration 0055 (two RLS-forced tenant tables), drizzle schema files, the journal/quarantine repository modules, a versioned `webhook-events` job payload, and an end-to-end test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SendGrid → public webhook route | Untrusted signed bytes cross here; the ECDSA signature and header timestamp are the only authority. |
| API request → Postgres (`ingress_journal`) | Verified-but-tenant-owned PII is persisted here; RLS is the isolation boundary. |
| API → Redis (BullMQ job payload) | Job payload now carries a journal id; a forged payload could point at another workspace's journal row. |
