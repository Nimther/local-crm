<objective>
Close the **write-path half** of WR-06 (D-01, D-02): pin `TimeZone=UTC` on every Postgres
connection the monorepo's single mandatory pool factory opens, and prove it behaviorally
against a Postgres database whose own default timezone is deliberately NOT UTC.

Purpose: WR-06's real hazard lives entirely in the write path. `now()` is a `timestamptz`;
coercing it into a naive `timestamp` column (`contacts.created_at` and siblings) uses the
**session's** `TimeZone` GUC. With no pin anywhere in the connection stack, a Postgres server
or database whose default timezone is ever non-UTC silently stores local wall-clock values,
and every day-bucketed metric derived from those columns shifts. `createPgPool` is the one
choke point every pool in the repo already goes through (enforced by the existing
`lint:pg-pool-factory` CI gate), so the pin lands once and covers `apps/api`, `apps/worker`
and every operator CLI in `packages/db/scripts`.

Output: `packages/db/src/pool.ts` pinned via the Postgres startup-parameter form, a new
non-UTC behavioral regression test, and a Docker-less config-level guard so the pin is
provable even where a live Postgres is unavailable.

**Tracer note (TRACER_MODE=true, recorded deviation):** Task 1 is this phase's single
`type="tracer"` task — the thinnest end-to-end slice through every layer the WR-06 track
touches (pool-factory config -> Postgres startup handshake -> a real naive-timestamp write ->
read-back assertion), carrying a real runnable end-to-end `<verify>`. It deliberately does NOT
span the phase's other two tracks (the CI-built `megacrm-postgres` image, plan 17-03; the
restore-drill instrumentation, plan 17-04). Those are independent tech-debt closures with no
shared architecture with this one — there is no cross-track integration risk for a tracer to
retire, and a task pretending to wire them together would be theatre, not a proven slice.
One tracer, one architecture, honestly scoped.
</objective>

    **Provisioning (top of file, module scope, mirroring `pg-tls.test.ts`):** call
    `createEphemeralDatabase({ workspace: "pg-timezone" })`. Open a short-lived admin
    `Pool` on `provisioned.adminDsn`, run

    **Scratch table:** the ephemeral database has no migrations applied, so create the probe
    table inside the test rather than depending on `contacts`. Use a table named `tz_probe`
    with a `timestamp` (no time zone) column defaulting to `now()`, plus a text discriminator
    column so the two writes are distinguishable. Reproduce the exact column-type situation
    WR-06 describes: naive `timestamp`, value derived from `now()`.

    **Assertions:** query `SHOW TimeZone` through each pool for the two session-posture cases.
    For the stored-value case, read the naive column back as text (cast to `text` in SQL so no
    driver-side timezone interpretation can enter the comparison) and compare against a UTC
    string built in JS from `new Date()`. Compare at date+hour granularity, not to the second,
    so the test is not clock-race-flaky. Because `America/New_York` is offset from UTC by a
    whole number of hours, the pinned and unpinned stored values differ by that offset and the
    hour comparison discriminates cleanly.

    **Then pin the factory:** in `createPgPool` (`packages/db/src/pool.ts`), add
    `options: "-c TimeZone=UTC"` to the existing `new Pool({ connectionString, max })`
    construction. Do not add any other key; in particular do not introduce an `ssl` key —
    the module header's "TLS: exactly one mechanism" rule still governs.

    Use the startup-parameter form, NOT a post-connect event handler that issues a session
    statement. node-postgres forwards the `options` string verbatim in the Postgres startup
    packet, so the GUC is applied during the connection handshake, before any query can run on
    that connection. The event-handler alternative is a documented race
    (brianc/node-postgres#3265): the connection can be handed out of the pool while the
    statement is still in flight, so the timezone silently fails to apply on some fraction of
    connections.

    Extend `pool.ts`'s module-header comment with a new titled section, matching the existing
    TLS and error-handler sections' depth and citation style: state that the pin exists for
    WR-06 (D-01), name the two mechanisms considered, cite issue 3265 as the reason the
    startup-parameter form was chosen, and record that `packages/db/src/partitions/relocate-default.ts`
    already establishes the companion read-site idiom (plan 17-02 applies it to the growth
    query). Also record the PgBouncer revisit trigger from RESEARCH.md: there is no external
    pooler anywhere in this topology today (DB-14 deferred to SCALE-02), and transaction-mode
    pooling can restrict non-default startup parameters via its own `ignore_startup_parameters`
    setting — so this pin must be re-verified against a real backend connection if a pooler is
    ever introduced.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application process -> Postgres session | Session GUCs (`TimeZone`) are negotiated across this boundary; whatever is not pinned here is inherited from server/database defaults the application does not control. |
| Postgres session -> stored naive `timestamp` column | The coercion of a `timestamptz` (`now()`) into a naive column happens here, using the session's `TimeZone`. This is where WR-06's data-integrity defect is actually written. |
| test process -> shared Postgres cluster | Every ephemeral test database in this repo is provisioned against ONE cluster; a cluster-scoped mutation would cross into other concurrently running tests' sessions. |
