<objective>
Close the code half of T-14-73 (D-09): make `scripts/restore-drill.sh` record its own
restore-to-ready wall-clock duration and scratch-PGDATA disk high-water mark on every run, and
point the drill at the CI-built GHCR image plan 17-03 introduced.

Purpose: T-14-73 has been an open register row since 2026-08-14 for one reason — the figures
depended on an operator noticing and writing them down during a live session, and at plan
14-11's checkpoint approval nobody did. The runbook's own step 8 already claims the duration is
"printed inline" by the script; it is not. Instrumenting the script removes the human-memory
failure mode permanently: this phase's drill (plan 17-05) fills the placeholder, and every
future drill records its own figures whether anyone remembers or not.

The drill also currently launches `megacrm-postgres:${POSTGRES_IMAGE_TAG:-local}`. After plan
17-03 that reference names an image production no longer builds — and its `:-local` fallback
would silently run a stale host-built image, resurrecting exactly the T-14-88 surface this phase
closes. The drill must launch the same registry image production runs, and refuse to start
otherwise.

Output: additive instrumentation inside the existing `run_real_drill`/`wait_for_scratch_ready`
structure, Docker-less test coverage for both the success and the timeout path, a corrected
image reference with fail-loud guards, and a runbook that stops asking the operator to observe
what the script now records.

**Metrics format (Claude's discretion per CONTEXT.md; RESEARCH.md assumption A1).** Two
destinations, both cheap: the figures are printed inline on stdout (making the runbook's
existing step-8 claim true), and one JSON object per run is appended to
`RESTORE_DRILL_METRICS_FILE`, defaulting under `XDG_STATE_HOME` exactly as
`RESTORE_DRILL_BASELINE_FILE` already does — outside the repo working tree, so drill artifacts
never become an accidental commit. The operator sees this format at plan 17-05's checkpoint and
can ask for a different one before it is relied upon.
</objective>

    mountpoint — the container's own user already has full access to that filesystem, and the

    pipeline would otherwise kill the script. Redirect stderr away, append a fallback so the
    substitution always succeeds, and treat an empty or non-numeric result as "no sample" rather

    readiness check, and once more immediately after the loop exits by either path. Sampling
