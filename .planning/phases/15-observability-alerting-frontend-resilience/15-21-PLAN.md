<objective>
Close verification gaps **G-15-2** and **G-15-3**: two documents describe mechanisms the codebase no longer has, because the fix commits that changed those mechanisms did not update the docs in the same change — the exact violation `.claude/CLAUDE.md` forbids.

- **G-15-2 — ARCHITECTURE.md §18.** It states that `processor-wrapper.ts` substitutes the BullMQ job's own id for `requestId` when a job payload carries none. The WR-03 fix (commit `eaaafe0`) deliberately removed that substitution because it made `requestId` indistinguishable from `jobId` in every log line and Sentry tag for every queue except the two send lanes; `apps/worker/src/processor-wrapper.ts:196` now reads the payload value and nothing else. The same section also asserts a universal four-identifier coverage that was never true for `sendId`.
- **G-15-3 — SPECIFICATION.md §3.** The `SENTRY_DSN_API`/`SENTRY_DSN_WORKER`/`SENTRY_ENVIRONMENT` rows (≈L483-485) describe compose-level `${VAR}` interpolation inside each service's `environment:` block. The CR-01 fix (commit `32d2b22`) removed those three names from both `environment:` blocks precisely because that mechanism resolves from the invoking shell — not from `MEGA_CRM_ENV_FILE` — and, since `environment:` overrides `env_file:` for the same key, it overwrote the operator's real DSN with an empty string on every deploy while `scripts/deploy.sh` exported none of the three. The document therefore instructs an operator toward the shape that silently disabled error tracking.

This plan runs LAST in the gap-closure sequence on purpose. Plans 15-19 and 15-20 bind `sendId` on the dispatch and webhook paths; the §18 rewrite must state where that field now IS and IS NOT present, which is only knowable once both have landed. Scoping §18 down to "sendId is not bound anywhere" would close the gap by writing a new falsehood.

Purpose: the correlation model and the secrets-delivery mechanism are both read during incidents by someone who cannot check the source first. OPS-15's runbooks and OPS-08's Sentry topology are only as good as the documents an operator reaches for at 3am.

Output: a §18 that describes the shipped correlation model field by field with its real boundaries, a §7 with no surviving copy of the same two stale claims, and three §3 rows that match `docker/docker-compose.prod.yml`.
</objective>
