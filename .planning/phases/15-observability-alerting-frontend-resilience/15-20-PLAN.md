<objective>
Close verification gap **G-15-1**, webhook half. `apps/worker/src/queues/webhook-events.worker.ts` is 844 lines that manipulate `sendId` throughout — extraction, live-send re-resolution, FK nulling, per-event side effects — and contains **zero** structured logger calls of any kind. The one place in this system where an external provider tells us what happened to a specific send is the one place that never says which send it is talking about in a log line.

Plan 15-19 made a send's identifier greppable at dispatch. This plan makes it greppable at the other end of the send's lifecycle, so a single Loki query on one `sendId` returns both "we handed this send to SendGrid" and "SendGrid told us this happened to it" — which is what success criterion 1 ("a single send can be followed ... using one correlation identifier") actually requires, and what OPS-11 names `send_id` for.

The binding point is not arbitrary. A webhook job is a BATCH of events belonging to many different sends, so a scope opened around the batch or around the transaction would stamp one arbitrary send's identifier onto every other send's lines — confidently wrong correlation, strictly worse than the current absence. The correct point is per event, immediately after the loop's defensive re-resolution proves the event maps to a live `sends` row in this workspace.

Output: one per-event `withCorrelation({ sendId: send.id })` scope, one Pino line inside it, a suite that captures real Pino output and proves the field lands, and the SPECIFICATION.md §7 entry filed in the same change.

**Scope boundary.** The dispatch-side binding is plan 15-19 (already landed — this plan depends on it). The two stale docs are plan 15-21. All three edit SPECIFICATION.md, which is why they run in strict wave order.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SendGrid (external, untrusted) -> `send_events` row -> log call site | Every field on an ingested event is attacker- or provider-controlled text; `reason` and `payload` in particular are freeform |
| worker process -> stdout -> Alloy -> Grafana Cloud Loki | Anything added to a log line leaves the VPS for a third-party store |
| one tenant's event -> another tenant's correlation scope | A batch is workspace-scoped, but a single batch spans many sends; a mis-scoped binding mislabels which send a line belongs to |
