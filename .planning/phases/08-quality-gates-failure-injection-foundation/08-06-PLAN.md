## Phase Goal

Any change to the send pipeline can be proven safe before it ships — CI blocks broken code, tests cannot touch the dev database, and every failure mode the audit names can be reproduced on demand.

This plan removes the last code path by which a test can reach the dev database, and gives every DB-touching workspace its own ephemeral database.

## Artifacts this phase produces

- `packages/test-support/src/db-fixture.ts` exporting `ensureTestDbMigrated()`, `getTestDatabaseUrl()`, `createTestPool()`, `MIGRATION_ADVISORY_LOCK_KEY`
- `packages/test-support/src/__tests__/db-fixture-isolation.test.ts`
- devDependency edge `@mega-crm/test-support` → `apps/api`, `apps/worker`, `packages/delivery-core`

<objective>
Collapse the three near-identical `db-fixture.ts` copies into one module inside `@mega-crm/test-support`, delete the `TEST_DATABASE_URL ?? DATABASE_URL` fallback that all three carry, and register `globalSetup` in the two vitest configs that still lack it — so every DB-touching workspace provisions and tears down its own ephemeral database.

Purpose: the fallback is the literal mechanism by which a test run reaches the dev database today (SPEC R4 Current state). Removing it from one shared module is the second of the two guard layers D-14 requires; the first (globalSetup) is already in place.
Output: one fixture, three thin re-export shims, per-workspace ephemeral databases, and no `?? DATABASE_URL` anywhere in test scaffolding.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test scaffolding → dev database | The `?? DATABASE_URL` fallback in three files is the live code path by which a test run writes to real dev data today |
| Test entrypoint bypassing globalSetup | A test invoked directly (single-file `vitest run`, an editor runner, a script) may skip globalSetup entirely — the fixture-level guard is the second layer that catches it |
| Workspace A's suite → workspace B's rows | A shared ephemeral database plus parallel `--workspaces` execution lets one suite truncate another's fixtures mid-assertion |
