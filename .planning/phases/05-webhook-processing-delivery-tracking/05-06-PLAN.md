<objective>
Close Gap 1 from 05-VERIFICATION.md (WR-01 / WR-02): make the webhook worker's
per-event `occurred_at` deterministic-or-absent so the exactly-once dedup
guarantee (WBHK-03 / D-09) holds for events whose SendGrid `timestamp` field is
missing, non-numeric, or numerically out of range.

Two defects, one root cause in `extractEventRow`:
1. A missing/non-numeric `timestamp` falls back to `new Date().toISOString()`
   (wall-clock, non-deterministic). A BullMQ/SendGrid redelivery of that event
   computes a DIFFERENT `occurred_at`, `ON CONFLICT (workspace_id, sg_event_id,
   occurred_at)` never fires, and the event is re-inserted with duplicate
   counter increments and duplicate suppression side effects.
2. A numeric-but-out-of-range `timestamp` (e.g. `1e20`) makes
   `new Date(ts * 1000).toISOString()` throw `RangeError` inside
   `.map(extractEventRow)`, crashing the whole job; BullMQ retries 5× then
   permanently drops the ENTIRE already-acked batch, including well-formed
   events.

Fix: `extractEventRow` returns `null` (skip the event, exact same treatment as a
missing `sg_event_id`) whenever `timestamp` is not a finite number within the
Date-representable range. It never substitutes wall-clock time.

Purpose: restore the WBHK-03 exactly-once invariant this phase exists to
guarantee, under the exact trigger conditions no existing test covers.
Output: hardened `extractEventRow` + two regression tests, both green.

Coverage audit (gap-closure scope): GOAL = phase truth #3 (deduplicated
delivery outcomes, missing/invalid-timestamp case) → this plan. REQ = WBHK-03 →
this plan. RESEARCH/CONTEXT = D-09 (exactly-once counter/suppression), D-14
(dedup key) → this plan. No unplanned items; full-phase requirement coverage
already satisfied by executed plans 05-01..05-05.
</objective>
