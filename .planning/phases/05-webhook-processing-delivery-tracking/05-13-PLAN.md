<objective>
Close the single major gap from 05-UAT.md round 5 (Test 4): a delivered+opened
test-campaign email left campaign metrics at zero — "последнее событие
обновляется, но в тестовой кампании события по нулям".

Root cause (confirmed in .planning/debug/campaign-metrics-zero-despite-events.md
against live UAT data): SendGrid's Event Webhook delivers the mail/send custom
args FLATTENED into the event JSON root — `send_id`, `workspace_id`,
`campaign_id`, and `test` arrive as TOP-LEVEL fields, and there is no nested
`custom_args` object in webhook payloads. `extractEventRow` reads
`event.custom_args?.send_id`, which is always `undefined` for a real event, so
every event is stored with `send_id = NULL`. The side-effect loop then skips it
(`if (row.sendId === null) continue`), so sends fact columns and campaign
counters never update — while `debounceWebhookHealth` still fires per batch,
producing exactly the reported split (last-event timestamp updates, metrics stay
zero). Every existing webhook test fixture encodes the same wrong nested shape,
which is why 100% of automated tests passed against a payload SendGrid never
sends, and the bug survived until live UAT.

Fix (three coupled changes, RED→GREEN):
1. RED — add an integration test that replays a verbatim FLATTENED SendGrid
   payload (top-level markers, no `custom_args`) through the real worker and
   asserts attribution + counter increments. It fails against the current
   worker.
2. GREEN — `extractEventRow` reads `send_id` and the test marker from the event
   top level (keeping the existing UUID validation), with the nested
   `custom_args` read demoted to a defensive fallback. Turns the RED test green.
3. Migrate every existing webhook test fixture to the real flattened shape so
   the suite exercises the shape SendGrid actually posts, and can never again
   pass against a fictional nested payload.

Purpose: restore end-to-end delivery attribution — the whole reason Phase 05
exists (WBHK-04 campaign metrics, SUBS-02 suppression, WBHK-02 send-side markers
round-tripping back through the webhook).
Output: corrected `extractEventRow`, a real-payload integration test, and
flattened fixtures across the webhook suite — all green.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-G5-01 | Spoofing | `extractEventRow` top-level `send_id` read (webhook-events.worker.ts) | medium | mitigate | A forged event could name an arbitrary `send_id` to falsely mark a message delivered/opened. The upstream raw-body ECDSA signature check (05-01) already authenticates that the payload genuinely came from the tenant's SendGrid account before it reaches the worker, so an unauthenticated attacker cannot inject markers. |
| T-05-G5-02 | Tampering / cross-tenant integrity | batch send-resolution SELECT | high | mitigate | A payload could carry a `send_id` belonging to another workspace. Unchanged mitigation preserved by this plan: the resolution SELECT is `WHERE workspace_id = <job workspace> AND id = ANY(...)`, and any id that does not resolve within the job's own workspace is nulled out (D-15), so a foreign/orphan send_id can never attribute a fact or counter across tenants. This plan only changes WHERE the id is read, not the workspace-scoped resolution that follows. |
| T-05-G5-03 | Information Disclosure (integrity of reported metrics) | campaign counters / sends fact columns | high | mitigate | The bug itself was an integrity failure: real delivery outcomes silently dropped, so marketers saw zeroed metrics. Fix restores accurate attribution; the new attribution test + migrated real-shape fixtures prevent the false-zero regression from recurring. |
| T-05-G5-SC | Tampering | npm/pip/cargo installs | low | accept | Logic-only change to an existing worker file plus test-only edits/additions — no new package installs, so no package-legitimacy checkpoint is required. |
</threat_model>
