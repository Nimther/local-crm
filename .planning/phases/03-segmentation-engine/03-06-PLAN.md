<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/API client → segments evaluation routes | Session-authed but a member can submit arbitrary (unsaved on preview, saved on create/update) definitions that compile to expensive queries against tenant data. |
| route handler → tenant DB pool | Every evaluation holds a pooled connection; without a bound, a pathological definition holds it indefinitely (T-03-04). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Denial of Service | POST/PATCH/GET-members evaluation | high | mitigate | statement_timeout (SAVE_EVAL_STATEMENT_TIMEOUT_MS) on every evaluation path + 57014→4xx mapping; a pathological definition can no longer hold a tenant-pool connection unbounded (WR-03). |
| T-03-13 | Denial of Service / error amplification | unknown-field payload over HTTP | high | mitigate | 03-05 allow-list makes the unknown/empty standard field a 400 at the boundary; this plan proves it over HTTP so it can never reach SQL as a compiler throw → 500 (CR-01). |
| T-03-14 | Information Disclosure | 4xx error body on canceled/expensive evaluation | low | accept | The error body is a generic "definition too expensive" message with no query internals or tenant data; React/API do not echo the compiled SQL. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages this plan — reuses apps/api's existing vitest test harness and pg driver. |
</threat_model>
