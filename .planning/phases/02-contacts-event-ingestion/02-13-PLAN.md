## Phase Goal

**As a** marketer filtering my contact base, **I want to** type a name or email into the list search and keep typing without the field losing focus or the page flashing, **so that** I can search by typing normally instead of pasting a pre-built value.

<objective>
Close UAT Test 2 (major): the contact list search input loses focus and the whole page "refreshes" on every debounced keystroke. Root cause (diagnosed in `.planning/debug/contact-search-focus-loss.md`): `ContactsListPage` has a full-page skeleton early-return on `contactsQuery.isLoading` that sits ABOVE the search toolbar in the render tree, and the contacts `useQuery` lacks `placeholderData: keepPreviousData`. In TanStack Query v5, every debounced search change produces a new `queryKey` with no cached data → the query re-enters `isPending`/`isLoading` → ~300ms after each typing pause the entire page tree (including the focused `<Input>`) is unmounted and replaced by skeletons → the browser drops focus to `<body>`.

This HARDENS an already-satisfied requirement (CONT-01 / D-13 contact list search) — it is not re-claiming it (gap-contract rule 5), so `requirements` is intentionally empty. The list search itself works; only the focus/remount behavior during refetch is defective.

Purpose: make character-by-character typing in the list search behave normally (focus retained, no page flash), which is the concrete behavior UAT Test 2 requires.
Output: a `keepPreviousData`-backed list query, a render structure that keeps the toolbar/search input mounted unconditionally with an initial-load skeleton scoped to the results region only, a lightweight refetch dim cue, and a Playwright regression that reproduces then guards the fix.
</objective>
