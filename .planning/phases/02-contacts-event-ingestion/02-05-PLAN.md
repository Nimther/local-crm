<objective>
Stand up the phase's shared async foundation — extract the tenant-context/pool into a package both the API and a new worker process import, add Redis + BullMQ, and scaffold the separate `apps/worker` process — so that event ingestion (02-06) and CSV import (02-07) can run their processing off the request path without the API and worker ever drifting on tenant-scoping logic. Because this introduces new npm dependencies flagged SUS by the legitimacy audit, installation is gated behind a blocking-human checkpoint.

## Phase Goal

**As a** marketer, **I want to** build and maintain my contact base through the UI, CSV import, and a server-side API — while my product backend streams freeform behavioral events — **so that** my contacts are created and enriched in real time and every contact carries an accurate subscription status.

This is the shared-foundation exception to vertical slicing (CONTEXT.md explicitly scopes "adding Redis + the BullMQ worker AND its process" as in-phase infra): the event and CSV slices that follow both consume this queue + worker + shared tenant-context. It is paired tightly — consumed in the very next wave — rather than built speculatively.

Purpose: The extraction prevents two independent tenant-scoping implementations (RESEARCH Structure Rationale / PITFALLS Pitfall 8); the queue/worker is the reusable pipeline the Phase 4 send loop also builds on.
Output: @mega-crm/tenant-context package, Redis infra + REDIS_URL wiring, apps/worker scaffold, shared queue constants.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → Postgres | The worker opens its own tenant transactions; it must use the identical RLS mechanism as the API |
| build/supply chain → runtime | New npm dependencies (bullmq/ioredis/@bull-board/csv-parse) enter the trust boundary |
| app → Redis | Queue backend; connection string is an operational secret (REDIS_URL) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05-SC | Tampering | npm installs (bullmq, ioredis, @bull-board/*, csv-parse, @fastify/multipart) | high | mitigate | Blocking-human legitimacy checkpoint (Task 1) verifies each package/registry/version before any install; not auto-approvable |
| T-02-05-01 | Information Disclosure / Elevation of Privilege | worker inventing its own tenant-scoping | high | mitigate | Single shared @mega-crm/tenant-context package; worker imports it, never re-implements set_config (RESEARCH Structure Rationale) |
| T-02-05-02 | Denial of Service | API booting without a reachable Redis | low | mitigate | REDIS_URL is Zod-required at boot (env.ts) and by the pre-dev check; missing config fails loudly before listen |
</threat_model>
