<objective>
Prove the whole rotation architecture end-to-end on one thin vertical slice: extend `verifyUnsubscribeToken` from a single-secret compare into an ordered, exhaustively-evaluated `[primary, ...previous]` candidate loop (D-01, D-04), add the package-local logger that D-05's previous-secret-match line needs, and prove BOTH link eras redeem through the real `POST /unsubscribe/:token` route after a simulated two-step rotation (D-08).

Purpose: this is the phase's architectural bet — that lazy `process.env` reads inside `packages/delivery-core` let a *running* API process verify a token signed by a secret it no longer signs with, and that the route layer needs zero changes because the null-or-payload contract is preserved. If that bet is wrong, it must fail here, on the first commit, not after the env-validation, redaction and documentation layers are already built on top of it.

Output: a working multi-secret verifier, a package-local pino logger, an end-to-end route test covering both link eras, and the SPECIFICATION.md filings that the same-change rule binds to *this* commit (the new `pino` dependency and the new env var's first reader).
</objective>

## Trust Boundaries

| Boundary | Description |

| public internet → `POST /unsubscribe/:token` | An unauthenticated, attacker-controllable token string crosses here; possession of a validly-signed token is the entire authorization for the mutation. |
| operator environment → process env | `UNSUBSCRIBE_TOKEN_SECRET` and `UNSUBSCRIBE_TOKEN_SECRET_PREVIOUS` cross here at boot; the process never re-reads them from anywhere else. |
