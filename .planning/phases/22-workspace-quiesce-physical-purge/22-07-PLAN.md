<objective>
Finish PRG-02's reach into the auth tables: a purged workspace's `member` rows and its pending `invitation` rows (whose invitee email addresses are personal data) are destroyed, while Better Auth's `user`, `session` and `account` rows — global identities that may belong to other workspaces — are left completely alone.

This is the one part of the purge that structurally cannot run on the worker's ordinary connection. Migration 0045 revoked all privileges on `organization`, `member`, `invitation` and `user` from `mega_crm_app` and re-granted only `SELECT` on all four plus `UPDATE` on `organization` — the deliberate Phase 10 Better Auth trust boundary. A plain delete through the worker's normal pool fails with Postgres permission-denied 42501.

**PT-01 is resolved here as option (b): a dedicated pool authenticated as the existing `mega_crm_auth` role.** The alternative — a small migration granting `DELETE ON member, invitation TO mega_crm_app` — is cheaper to write but hands that capability to every code path `mega_crm_app` fronts, forever, to fix one worker function. Option (b) keeps the blast-radius argument that made the boundary worth having, reuses a role that already holds exactly these grants rather than inventing one, and follows the `relocate-default.ts` precedent of a purpose-scoped elevated connection. The undo cost is one pool and one config line, so this is `costly`, not a one-way door.

Deployment finding, verified rather than assumed: `AUTH_DATABASE_URL` already exists in `docker/prod.env.example`, is already in `scripts/check-env.mjs`'s required list, and the worker service in `docker/docker-compose.prod.yml` already receives the whole env file via `env_file:` — so no compose change and no new operator action is needed. The DSN is read lazily at pool creation with an explicit error, mirroring `packages/tenant-context/src/scan.ts`'s handling of `SCAN_DATABASE_URL`, rather than being added to the worker's boot schema; that keeps a process that mostly never purges from refusing to boot over a credential only one code path uses.

Purpose: PRG-02's D-12 clause.
Output: the scoped auth pool and its two deletes, wired into the purge before the tombstone, with an integration test that proves the trust boundary still refuses the ordinary pool.
</objective>
