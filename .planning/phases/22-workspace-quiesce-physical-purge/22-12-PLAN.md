<objective>
Close verification gap 1: `dead_letter_jobs.payload` can hold raw contact PII
from any terminally-failed job, the table is outside every purge list, and it is
undocumented in both `docs/PII-INVENTORY.md` and the purge runbook's survivor
table — silently contradicting the phase's own claim that a purged workspace's
PII is gone.

**The recorded decision: option (b) — an explicit retention policy on the
dead-letter table's own timer, plus the documentation the same-change rule
requires. Option (a) is declined.** Rationale, grounded in what the codebase
actually contains rather than in which fix is smaller:

1. **There is no retention on this table at all today.** `grep` for a delete
   against `dead_letter_jobs` across the repo returns exactly one hit, in a test
   teardown. Rows written since Phase 12 accumulate forever. The real defect is
   therefore not merely "the purge misses this table" — it is unbounded PII
   retention for **every** workspace, live or purged. Option (a) fixes only the
   purged-workspace slice and leaves the larger problem in place.
2. **Option (a) is structurally incomplete.** A `workspace_id` backfilled from
   `payload->>'workspaceId'` is derivable only for tenant-scoped job payloads;
   tick jobs enqueue `{}`, and any payload without that key would be left with a
   NULL `workspace_id` — an undocumented PII residue of exactly the kind this gap
   is about.
3. **Option (a) contradicts a deliberate, documented design.** Migration 0054's
   header and its `COMMENT ON TABLE` both state the absence of `workspace_id`
   and RLS is intentional, and name the additive column as the correct remedy
   *only* if per-tenant visibility is wanted. Nothing here wants per-tenant
   visibility; we want the PII gone. Choosing (b) keeps (a) fully available
   later — this decision forecloses nothing.
4. **Option (b) yields a checkable SC2 claim, not an asserted one.**
   `DEAD_LETTER_RETENTION_DAYS` is boot-validated to be at most
   `WORKSPACE_PURGE_RETENTION_DAYS`. Because quiesce (SC1) stops all work for a
   soft-deleted workspace, every dead-letter row that existed when a workspace
   was soft-deleted is provably expired before that workspace's purge is ever
   eligible. That invariant is enforced by the boot validator, not by prose.

Purpose: make the PII lifetime of `dead_letter_jobs` bounded and written down,
so an auditor finding (or not finding) rows there can tell correct-by-design
from purge-incomplete.

Output: a bounded retention sweep on the existing purge tick, one new boot-
validated env var, and four documents reconciled in the same change.
</objective>
